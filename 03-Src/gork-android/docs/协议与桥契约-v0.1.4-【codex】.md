# Gork Android 协议与桥契约（实施中）

版本：v0.1.4-dev；日期：2026-09-27。协议来源为根项目 `tools/stopwatch_ble.py`、`tools/stopwatch_sound.py`、`tools/stopwatch_audio.py`、`tools/stopwatch_opus.py` 及现有固件源码；本稿描述源码候选，不代表手机实测。

## BLE 协议

| 服务 | Service | Write | Notify |
|---|---|---|---|
| 表情/文字 | `48f1a001-8a75-4db6-9c18-590f7e9b0a01` | `48f1a002-8a75-4db6-9c18-590f7e9b0a01` | `48f1a003-8a75-4db6-9c18-590f7e9b0a01` |
| 内置短音 | `48f1c001-8a75-4db6-9c18-590f7e9b0a01` | `48f1c002-8a75-4db6-9c18-590f7e9b0a01` | `48f1c003-8a75-4db6-9c18-590f7e9b0a01` |
| 动态音频 | `48f1b001-8a75-4db6-9c18-590f7e9b0a01` | `48f1b002-8a75-4db6-9c18-590f7e9b0a01` | `48f1b003-8a75-4db6-9c18-590f7e9b0a01` |

- 表情命令为 ASCII，最多 20 字节；`once` 可省略前缀，`loop`、`pingpong` 显式带前缀。`sleepy` 回执名为 `DROWSY`，`dizzy` 为 `PLAYFUL`。文字用 F0 begin、F1 chunk（每包 17 数据字节）、F2 commit、F3 clear；最多 24 BMP 字符及 72 UTF-8 字节。旧协议表情回执没有请求编号，只能串行发送、匹配预期回执，超时断开隔离迟到通知。
- 短音帧为 `<BBHIB>` 小端 9 字节；id 为 1–65535。PLAY=3，STOP=4，SET_VOLUME=5；1–6 为内置短音，音量 0–100。只把匹配 id 且属于本次操作的终态回执作为确认；设备完成回执仍不等于用户实际听到。
- 动态音频帧为 `<BBHII>` 小端，最大 244 字节，PCM 16-bit 单声道 16/24 kHz、0.1–10 秒、最多 480000 字节。v0.1.1 可手选 WAV 作 PCM 实验：协商 MTU 后 HELLO/CAPS，DATA 只按设备 ACK 字节偏移推进，COMMIT 确认后 PLAY，最后等 PLAYED；180 秒总限时、写入/ACK 5 秒、播放终态 15 秒，中止则断开同一 GATT。v0.1.2 增加最多三包应用窗口；Android GATT 写入依旧逐次回调串行，ACK 可以跨过丢失的单个回执。系统中文 TTS 完整文件导出和 PCM16 单/双声道 8–48 kHz 转换后，对应文字须在同一设备任务中等 COMMIT 回执，再按 F0/F1/F2 完整确认，才发 PLAY。Opus 需 HELLO 协商，使用长度前缀原始 Opus 包和 pre-skip，不是直接发 Ogg；当前尚未实现 Opus、AI 或云 Provider。
- Python 导出的金向量：`你好Gork`、事务号 7 → `f0070a` / `f10700e4bda0e5a5bd476f726b` / `f207`；短音 3、id 0x1234 → `010334120000000003`；音量 55 → `010534123700000000`；HELLO 示例 → `01010df078563412efcdab90`。Android `WatchProtocolTest` 检查这些跨语言字节。

## NativeBridge v1 候选

页面 origin 固定 `https://appassets.androidplatform.net`，仅主 frame 可发消息。入站 JSON 最大 16 KiB，要求 `requestId`（1–64 个字母/数字/`-`/`_`）、非负 `generation`、`method`、`params`。响应统一 `{requestId,ok,result}` 或 `{requestId,ok:false,error}`；不通过桥返回聊天正文、录音或凭据。新页面仅用 generation 0 的 `capabilities.get` 握手获取原生代际号，其他请求必须携带当前代际；页面重载停止旧 BLE 任务和本机朗读。JS 侧按 requestId 管理超时，音频文件选择等待用户操作、由原生端控制传输超时。

当前白名单：`capabilities.get`、`state.get`、`preferences.get/set`、`device.scan/connect/disconnect`、`character.play/showText/clear`、`sound.play/volume/stop`、`audio.pickAndPlayPcm`、`speech.local.status/speak/stop/synthesizeProbe/toWatch/asr.status/asr.start/asr.release/asr.cancel`、`cloud.settings.get/set`、`cloud.consents.set`、`cloud.key.save/clear`、`cloud.ai.ask/cancel`、`task.cancel`。页面加载不主动扫描、配对、连接或重放历史任务。`device.connect` 只接受本次扫描产生的候选；Android `READY` 必须在三服务发现和三个 CCCD 写入成功之后。

当前实现尚未完成事件序号、后台连接、Opus 和真实 AI/云 Provider；T01/T03/T05/T06 不能标为全部通过。手机实测前，配对、系统权限与旧通知时序均保持未验证。

## v0.1.3 设备端 ASR 边界

- speech.local.asr.status 仅查询系统是否报告设备端识别服务，不代表已安装中文模型。speech.local.asr.start 仅使用 API 31+ createOnDeviceSpeechRecognizer，中文 zh-CN，缺失时显式失败，无联网识别器回退。首次显式使用请求 RECORD_AUDIO；页面卸载、进入后台、全局停止或取消时销毁识别器，30 秒无结果超时。
- 按住说话松开调用 speech.local.asr.release；Android 识别器可自行结束语句。结果最长 300 字，只填入手机草稿，不自动发送 Watch、AI 或上传。RECORD_AUDIO 能力、中文模型、断网行为、拒绝权限及后台中断均需目标手机 A12 实测。
- 依据：[Android SpeechRecognizer](https://developer.android.com/reference/android/speech/SpeechRecognizer)、[RecognitionListener](https://developer.android.com/reference/android/speech/RecognitionListener)。

## v0.1.4 文字 AI Provider 边界

- 新安装的四项许可均默认为关：AI 提问文字、录音上传、待合成文字上传、AI 回答文字上传。后三项为后续云 ASR/TTS 预留，当前没有对应网络入口。AI 请求必须用户在手机上保存 API Key、显式打开提问上传许可并点击发送按钮；结果只在手机文本区显示，不自动发 Watch。
- cloud.key.save 将个人 Key 用 Android Keystore AES-GCM 加密后写应用私有首选项；cloud.settings.get 仅返回是否配置，不返回 Key。根清单禁止备份/设备迁移。用户可清除 Key。桥只允许本地可信 origin 主 frame；网页 CSP connect-src 维持禁止，不由网页直接联网。
- 请求为可配置 HTTPS Chat Completions 接口、Bearer Key、非流式 JSON；默认地址参考项目现有百炼区域接口。禁止重定向；连接 10 秒、读取 10–60 秒，响应体最多 64 KiB，结果最多 1000 字。HTTP 错误只传状态码，异常不把服务端正文/Key带入页面或日志。取消/撤销许可断开连接并弃用旧任务结果。尚无真实手机或云调用，A13 未通过。
- 接口依据：[阿里云百炼 OpenAI 兼容调用](https://help.aliyun.com/en/model-studio/compatibility-of-openai-with-dashscope)、[Android Keystore AES-GCM](https://developer.android.com/reference/android/security/keystore/KeyGenParameterSpec)。
