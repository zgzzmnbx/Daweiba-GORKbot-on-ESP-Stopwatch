# v0.7.0 P0 音频探针：协议与操作

日期：2026-09-21。范围：可编译固件 + 纯 BLE 录放音测试工具；不是完整语音闭环，不关闭 P1–P4 真机门禁。

## 已实现的测试路径

1. 设备 Settings → Audio test；原 A/B 表情短按与 A+B 设置入口不变。测试页内 A 按住至少 250 ms 开始收音，松开结束；B 按下立即请求停止。只在电脑已 ARM 且之后出现新的本地按键动作时录音，不支持电脑直接启动麦克风。
2. 电脑 `echo`：设备录音 → BLE → 电脑内存 → BLE → 设备扬声器。不是电脑麦克风或电脑扬声器；不调用 8765/8766、不识别文字、不访问云端。
3. `tone`：下发半秒低幅度 440 Hz 测试 PCM；`play` 下发指定完整 WAV；`record` 把用户主动录制的音频保存到明确指定的新文件，拒绝覆盖已有文件。
4. 麦克风 16 kHz、PCM16、单声道；回放输入允许 16/24 kHz PCM16 单声道，扬声器由官方库按自身输出采样率处理。最长 10 秒、最短 0.1 秒；超长 WAV 拒绝，录音达到 10 秒自动停并明确提示。
5. 录放互斥；一次 PSRAM 缓冲 480,000 bytes，录音最多 320,000 bytes。队列 4 × 244 bytes，上下行信用窗口均为 1；这是为验证正确性的保守基线，不是实时吞吐方案。
6. 退出页面、B、CANCEL、失联、15 秒无心跳、错包/队列溢出均停止；先结束官方音频任务，再清空/释放 PCM。断连不会自动重录或重播。

P0 期间只在测试页运行，表情页面不录音、不改变原产品按键。完整工作台设备音频模式、语音会话占用/上传许可、录音状态表情联动、播放打断重录、可调音量与高吞吐多包窗口，留待 P1/P2 硬件数据确认后按原 PRD 实现。测试页固定扬声器音量 48/255，首次听验请勿贴近耳朵。

## 电脑怎么运行

2026-09-21 客户端修复 v0.7.1：原启动器不变，窗口会显示 `StopWatch BLE audio bench v0.7.1`。连接强制按音频 UUID 定向、无缓存发现；本机实测已找到新增服务及两个特征。此前“current device has no audio service”只代表当次发现缺失，不能判定烧录失败；无需因此重新烧录或删除配对。

2026-09-21 当前设备应用区已升级 v0.7.0-P0，写入与独立读回通过；尚待正常启动、录放音与 BLE 实测。其他仍运行 v0.5.0 的设备没有新音频服务，必须另行授权升级。

- 关闭旧 BLE 控制台，在 8766 工作台断开设备连接；不要同时争抢蓝牙连接。独立语音服务无须停止。
- StopWatch 开启 BLE；首次使用按现有流程本地 Pair，随后进入 Audio test 页面并保持在该页。
- 双击项目根目录 `start-ble-audio-test.cmd`，默认进行 echo 测试。程序提示就绪后在设备按 A 说一小句，松开等待回放；建议首次只说 1–2 秒。
- 完成一次测试即断开连接；再次测试重新运行。Ctrl+C 请求 CANCEL 并断开；设备 B 是最快的本地停止入口。
- 同一台设备固件新增 GATT 后如 Windows 服务缓存仍旧，先正常断开重连并重启设备。不要自动清绑定或删除系统配对；需要重配时另行确认。

PowerShell 在项目根目录运行：

```powershell
# 先测试扬声器；首次不要直接播放大音量文件
.\start-ble-audio-test.cmd tone
# 双向回声测试
.\start-ble-audio-test.cmd echo
# 完整录音落盘（该目录被 Git 忽略；文件必须尚不存在）
.\start-ble-audio-test.cmd record Codex-Temp\my-audio-test.wav
# 播放已有短 WAV；不自动转换其他音频格式
.\start-ble-audio-test.cmd play Codex-Temp\my-audio-test.wav
# 最小 ATT MTU 兼容性，仅建议极短录音；显著更慢
.\start-ble-audio-test.cmd --packet-bytes 20 echo
```

启动器复用已安装的 `.venv-companion`/Bleak 3.0.2，不安装系统驱动，不硬编码 MAC/COM。每次扫描；多个候选时要求 `--address` 选择本次发现的地址。文件名、原始 PCM、转写/服务密钥不写日志；工具只显示状态、长度和实测传输速率。禁止把 mock 测试打印的速率当硬件吞吐。

## GATT 与安全

保留既有 `48f1a001/a002/a003` 表情服务、命令和回执不变，增加独立音频服务：

| 对象 | UUID | 权限 |
| --- | --- | --- |
| 音频 service | `48f1b001-8a75-4db6-9c18-590f7e9b0a01` | 不额外广播，连接后发现 |
| input | `48f1b002-8a75-4db6-9c18-590f7e9b0a01` | 加密 WRITE / WRITE WITHOUT RESPONSE |
| events | `48f1b003-8a75-4db6-9c18-590f7e9b0a01` | NOTIFY；CCCD 读写须加密，无音频 READ |

所有音频写入还校验当前已绑定、已认证的连接；通知用 ESP-IDF 定向发给该连接，不使用 Arduino 广播型 `notify()`。第二连接存在时暂停音频通知。音频回调仅校验/复制入固定队列；I2S、PSRAM、屏幕在主循环处理。CANCEL 独立原子标志优先于数据队列。

本版仍沿用无输入输出的 secure-connections bonding，并非声称具备带数字核对的 MITM 保护。陌生端拒绝、通知订阅攻击和断线竞争仍需真机负向测试。

## 协议 v1（小端）

统一头 12 bytes：`u8 version=1, u8 opcode, u16 transfer_id, u32 epoch, u32 value`，剩余为 payload。总包长 20–244 上限协商；头本身可以只有 12 bytes。PCM 数据块须偶数字节。

- HELLO 请求 epoch=0；设备生成新非零随机 epoch。之后每包必须匹配它，物理连接 epoch 另在固件队列内隔离。旧连接/旧协议 epoch 的包不会执行。
- transfer_id 非零；ARM/BEGIN 必须比本次 HELLO 后任何旧 ID 大；达到 65535 必须重新建立会话，不回绕重用。
- HELLO 新会话会停掉旧音频，但不会直接录音或播放。CANCEL 是故障安全停止例外：当前认证控制端的 CANCEL 即使旧 epoch 也只能停，不可能启动动作。
- PC 最多一个正在等待回执的请求，心跳和新事务 ID 也在同一锁下排序；锁只覆盖一个包。数据 WRITE_NR 后必须收到 ACK 才发下一包，丢失/错位回执超时即失败，不重试 PLAY，也不自动续传。

| 操作 | value / payload | 回执 |
| --- | --- | --- |
| HELLO 1 | 请求包长 / 无 | CAPS 128：value=480000，payload=`u16实际包长,u16上限秒数10` |
| ARM 2 | 0 / 无，新 ID | ACK；本地 A 后 RECORDING 130，松开后 RECORDED 131 |
| PING 3 | 0 / 无，当前 ID | ACK；续 15 秒租约，PC 每 3 秒发送 |
| BEGIN 4 | 16000 或 24000 / `u32 PCM总字节数`，新 ID | ACK；不启动扬声器 |
| DATA 5 | 连续 byte offset / PCM | ACK value=下一个 offset；重复/乱序/越界错误即停 |
| COMMIT 6 | 总字节数 / 无 | 完整收到才 ACK，不完整绝不播放 |
| PLAY 7 | 0 / 无 | PLAYING 133，输出队列结束并等待 DMA 余量后 PLAYED 134；完成即清 PCM，不重复播放 |
| CANCEL 8 | 任意 / 无 | ACK，清队列与 PCM，停止录放 |
| PULL 9 | 录音 byte offset / 无 | AUDIO 132：value=同 offset，payload=PCM，最多协商包长−12 |

ACK=129，payload 为原请求 opcode 一字节；ARM/BEGIN/PING/CANCEL value=0，DATA 为下个偏移，COMMIT 为总长度。RECORDED 的 value 为完整录音长度，payload 一字节 0=正常松开、1=达到时长上限。Error=255，value：1格式、2状态/旧 ID、3资源/音频未配置、4长度/顺序、5驱动、6录音太短、7回调队列/包错误、8租约过期。

PLAYING 是设备已调用官方库并接受播放队列，非电脑传输完成；不能据此证明扬声器实际出声。PLAYED 使用队列状态 + 100 ms DMA 排空余量；是否不截尾须听验。PCM 经 20 ms 官方录音块采集，块间连续性、驱动吞吐及真机采样率仍需量测，不能只看 WAV 头断言收音已正确。

## 验收顺序

1. P0：自动化模拟测试、锁定工具链编译；不声称实测音质/FPS/吞吐。
2. G1：当次批准后识别设备，只写 app0 `0x10000`；不改分区/NVS/eFuse，不整片擦除。
3. P1：tone 听验 → 1–2 秒 echo → record 文件听验、电平/爆音/截尾、A/B/设置退出 → 10 秒上限。
4. P2：16/24 kHz 下行、20/244 包长、净吞吐/丢包、20 次取消、断连/陌生端订阅、PSRAM；原表情/气泡/触摸回归。单包窗口若吞吐不够，再实现有测量依据的多包窗口或压缩，不凭理论承诺实时。
5. P3/P4：才接 8766 设备音频模式与 8765 的本地 ASR/TTS，落实会话、上传许可和状态联动；现有页面仍使用电脑录音/电脑回读。

官方依据：工程锁定的 M5Unified `774d920` 中 `_microphone_enabled_cb_stopwatch` / `_speaker_enabled_cb_stopwatch` 和 StopWatch 引脚配置；[StopWatch 官方硬件](https://docs.m5stack.com/zh_CN/core/StopWatch)。同一 codec/引脚半双工切换必须先结束旧任务，不能同时启用 mic/spk 的共享音频时钟。
# v0.7.2-P0 补丁说明（2026-09-21，未烧录）

协议版本/UUID 不变。ERROR 的 value 新增：9 麦克风初始化失败；10 采集入队失败；11 采集块超时（超过 1000 ms）；12 扬声器初始化失败；13 播放入队失败。旧 code 5 保留为旧固件的通用驱动/采集错误。电脑工具 v0.7.2 同时显示代码和原因。错误后仍关闭麦克风/扬声器并释放 PCM；设备保留失败原因，直到重新进入页面、HELLO 或新 ARM/BEGIN。本次修复旧循环时间导致的立即超时误判，实际音频尚待真机复测。
