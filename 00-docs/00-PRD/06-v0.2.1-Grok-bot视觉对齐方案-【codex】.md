# v0.2.1 Grok bot 视觉对齐方案

> 状态：视觉基准已确认，待实现；不代表 v0.2.1 固件已构建或烧录。  
> 确认日期：2026-09-16  
> 当前设备固件：v0.2.0；其真机功能验收仍未完成。

## 1. 决策与依据

大尾巴确认：要 [Bible Strong Avatar Lab](https://avatars.bible-strong.app/) 中的 **Grok bot**，而不是把 `grok-icon-study` 的白色 blob 继续作为最终造型。工程底座仍为 KK StopWatch Avatar；改变的是角色视觉数据、表情/动画定义和对应的渲染层，不更换 StopWatch 底层驱动。

以仓库 [`smontlouis/bible-strong-avatar-lab`](https://github.com/smontlouis/bible-strong-avatar-lab) 的提交 `79fe9ba06e4874b11394b8e8a3f2c493c9d197ba` 为可复现的数据快照。权威输入为该提交的 `src/features/studio/defaultStudioDocument.json` 中名为 `Grok bot`、ID 为 `avatar-7874f78a-93ec-4536-a3b6-bb53ed744efd` 的角色及其默认行为库。项目当前 `Codex-Temp/bible-strong-avatar-lab-reference/` 仅是只读研究副本，不作为正式源码依赖。若网站后续更新，以锁定提交为实现依据；变更基准须另作记录。

该输入定义了黑色球形主体（240 × 240 × 240、roundness 1）、白色双眼、基础眼宽 20 / 高 50 / 间距 35 / 垂直位置 -7，以及 **27 个 expression preset、23 条 animation sequence**。sequence 还定义了步骤持续时间、过渡方式、循环模式和眨眼参数。它比当前工程使用的 Grok Icon Study 更适合作为本项目的视觉基准，因为它直接对应大尾巴指出的网页角色和动态表情；这是“目标匹配度更高”的判断，不等于网页引擎可原样运行在 ESP32-S3 上。

仓库采用 3D-inspired geometry + SVG/Motion 浏览器渲染。固件只移植可复现的角色/表情/时序语义，在圆屏上实现等价的 2D 投影和局部刷新；不要把 React、SVG DOM 或 Motion 运行时移入 MCU。来源与 AGPL-3.0 许可证须随转换数据和所复制代码保留记录；个人本地使用不是删除来源记录的理由。

## 2. 当前差距

| 维度 | v0.2.0 现状 | Grok bot 目标 |
| --- | --- | --- |
| 主体与眼睛 | `grok_renderer.cpp` 白主体、黑眼 | 黑主体、白眼；保持网页的简洁轮廓和眼部比例 |
| 几何 | Grok Icon Study 三角形主体与 8 组眼形 | Grok bot 球体投影及每眼独立尺寸、位置、倾角 |
| 表情 | 12 状态映射 8 组眼形 | 27 个 preset 为数据来源，23 条 sequence 可播放 |
| 动态 | KK 固定关键帧与局部刷屏 | 来源定义的 hold / transition / playback / blink + 克制的环境运动 |
| 验证 | v0.2.0 桌面预览及设备照片 | 同一时刻、同一表情的网页/桌面模拟/真机三方对照 |

仅把颜色反转，或继续把 23 条动画压成 8 组静态眼睛，都不能视为视觉对齐完成。圆形屏幕与黑色设备外壳会使纯黑主体边界不明显，应在桌面预览和真机对照中确定背景明度、轮廓留白与实际显示区域；不得凭空增加网页没有的夸张眉毛、嘴巴或炫光。

## 3. 实施边界与任务顺序

1. **冻结基准**：将上游提交、角色 ID、JSON 字段清单、27 preset / 23 sequence ID、许可证和获取日期记入 `01-assets/reference/`；保存 5 个代表性网页参考帧及其表情/时间点。先记录现有 v0.2.0 设备照片和未完成的真机验收项。
2. **确定性数据转换**：建立可重复运行的转换脚本，从锁定 JSON 只抽取 Grok bot 及其依赖的 expression/sequence；输出固定点或紧凑 C++ 表。校验引用、范围、数量、顺序和重复生成哈希；不手抄 27 套参数。
3. **桌面视觉原型**：先做 `idle`、`listening`、`thinking`、`happy`、`celebrate` 五个代表序列的静帧及时间轴预览。与网页同一时间点对照并修正投影、眼形、眨眼、主体比例和过渡曲线；桌面视觉门禁未过，不进入固件接入。
4. **固件渲染接入**：在现有 `03-Src/stopwatch-grok-avatar/` 内新增独立 Grok bot 数据/渲染层，保留 KK 的屏幕、输入、IMU、振动、电源管理、诊断和 dirty-rectangle 管线。替换角色绘制与表情调度，不重写硬件驱动或扩大分区变更。
5. **全量行为**：在五个代表序列达标后，接入全部 23 条 sequence 和 27 个 preset；保持源数据的步骤次序、hold/transition 时长、循环和眨眼设置。现有 12 个硬件触发入口可映射到其中的序列，但“可播放 23 条”与“12 个入口都有独立触发”需分别验证。
6. **构建与真机**：完成数据单测、桌面截图、清理构建、内存和刷新测量；在获得本次固件更新的明确确认并重新核对端口、MAC、恢复镜像后才能写入设备。记录固件 SHA-256、实际写入偏移、读回校验和真机视频/照片。不得把编译或写后校验称作视觉/交互验收。

## 4. 验收口径

- 角色辨识：黑主体、白眼、相对比例、位置和留白应与锁定基准的 Grok bot 一致；屏幕边缘无明显裁切、漏白或闪烁。
- 表情覆盖：27 个 preset 均能独立预览；23 条 sequence 均能按定义播放，步骤时长、循环模式、眨眼可从自动化数据核查，不以截图数量代替动态验证。
- 对照证据：至少 `idle`、`listening`、`thinking`、`happy`、`celebrate` 各保留网页参考帧、桌面同刻帧、真机同刻照片或视频；标注每项“符合/差异/原因/待改”。环境光与手机拍屏的色差应单独说明。
- 性能：沿用 v0.2.0 的 60 FPS 目标、5 秒窗口不低于 55 FPS、常规平均渲染低于 12 ms、30 分钟无重启/闪屏的验收口径；如无法达到，报告测量值和降级取舍，不暗自降低标准。
- 回归：触摸、A/B 键、IMU、振动、诊断入口和恢复路径不因视觉替换回退；v0.2.0 未完成的真机功能验收继续单列，不因 v0.2.1 改版自动算通过。
