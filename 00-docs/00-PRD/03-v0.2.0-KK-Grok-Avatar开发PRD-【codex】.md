## 1. 背景与目标

大尾巴希望把 M5Stack StopWatch 开发成一个 Grok 风格的小机器人。前期已完成硬件知识基线、M5Burner 安装、设备识别和当前 16MB Flash 完整备份。经 GitHub 调研，决定不从零实现，而以专为 StopWatch 开发的 KK Avatar 工程作为硬件与动画底座，并导入 Grok 角色研究仓库中的几何和视觉资产。

v0.2.0 的目标是形成一套可复现、可编译、可审计的固件源码，并在明确授权后完成首次设备写入和真机功能验收。截至本次记录，源码、构建、首次写入和写后 Flash 校验已经完成，真机功能验收仍待逐项观察和记录。

## 4. 用户故事

1. 设备开机后立即看到一个有生命感的 Grok 角色。
2. 触摸屏幕时，角色的眼睛和头部连续跟随手指，而不是松手后才响应。
3. 倾斜设备时，角色看向倾斜方向，眼睛先动、头部后跟。
4. 点击、双击、长按或滑动时，角色以不同表情和振动回应。
5. 摇晃设备时，角色出现眩晕反应，停止后平滑恢复。
6. 所有动作连续自然，没有明显闪屏、撕裂或硬切。
7. 通过串口命令切换状态，便于未来接入语音或其他控制器。
8. 如果新固件不满意，可以恢复到当前原始状态。

## 5. 功能需求

### FR-01 启动与基础画面

- 完成 M5Unified、M5PM1、M5IOE1、显示、触摸、IMU和按钮初始化。
- 正常启动后进入 `idle`，纯黑背景，无调试文字残留。
- 默认角色使用 Grok blob 身形和对应眼睛几何。
- 初始化失败必须通过串口和诊断模式给出可定位信息，不得静默黑屏。

### FR-02 Grok 几何与渲染

- 将 `geometry-data.js` 中的眼睛、身形和颜色数据转换为 C++ 常量数据；设备运行时不得依赖 JavaScript、HTML或浏览器。
- 原始资产、转换脚本和生成后的 C++ 数据分离保存，生成过程可重复。
- 首版至少接入1个主要blob身形、8组代表性眼睛和黑/白主视觉；完整25眼、18身形作为后续扩展数据。
- 渲染继续采用 KK 的局部脏矩形策略，不退回每帧全屏 `pushSprite`。
- 黑色 AMOLED 背景上使用白色/浅灰角色，必要时保留单像素灰阶边缘降低锯齿。

### FR-03 状态与表情

保留并适配 KK 的12种状态：`idle`、`listening`、`thinking`、`happy`、`excited`、`curious`、`confused`、`angry`、`surprised`、`sad`、`sleepy`、`dizzy`。

- `idle`、`listening`、`thinking` 为持续基础状态。
- 其他状态为短暂反应，完成后回到此前基础状态。
- 每种状态映射明确的 Grok眼睛、身体挤压、位移、旋转、眨眼和持续运动参数。
- 过渡必须可中断；快速连续输入时不能回到错误状态或卡死。

### FR-04 生命感动画

- 随机眨眼、微扫视、呼吸和轻微摆动。
- 眼睛、头部、身体位移、缩放、旋转和 squash 均采用独立弹簧或平滑时间轴。
- 眼睛跟随速度高于头部，形成前后层次。
- 动画使用固定微秒级帧调度，不以阻塞式 `delay` 驱动。

### FR-05 触摸交互

| 输入 | 预期行为 |
| --- | --- |
| 单击 | `happy` |
| 双击 | `surprised` |
| 长按 | `angry` |
| 按住移动 | 眼睛和头部连续跟随触点 |
| 左右滑动 | 预览并切换相邻表情 |
| 上滑 | `surprised` |
| 下滑 | `sleepy` |

- 滑动达到阈值时立即提交一次，不必等待松手。
- 未达到阈值时松手回弹，不误触切换。
- 圆屏边缘触摸需避免坐标越界。

### FR-06 IMU、按键和振动

- 使用 BMI270 加速度计和陀螺仪融合控制视线与头部倾斜。
- 只有连续、方向交替的强力横向摇晃触发 `dizzy`；拿起、放下和单次甩动不得误触。
- A/B 键浏览上一/下一表情。
- 长按 A+B 进入和退出硬件诊断模式。
- 关键动作提供短振动反馈；振动控制不得阻塞动画帧。

### FR-07 串口控制

- 波特率 `115200`。
- 支持输入12个英文状态名。
- 支持 `once <expression>`、`loop <expression>`、`pingpong <expression>`。
- 串口状态事件与后续语音层解耦，不在动画引擎中写死语音逻辑。

### FR-08 诊断模式

- 显示设备型号、屏幕尺寸、触摸坐标、IMU值、按钮和振动状态。
- 输出实际FPS、平均/最大渲染耗时和最大帧间隔。
- 诊断模式与产品画面分离，退出后恢复此前基础状态。

## 6. 非功能要求

### 性能

- 目标帧率：`60 FPS`。
- 稳态验收：连续5秒窗口不低于 `55 FPS`，平均帧间隔接近 `16.67 ms`。
- 常规表情平均渲染耗时应低于 `12 ms`；复杂状态不得持续低于 `45 FPS`。
- 不使用完整466×466画布每帧全屏传输作为最终方案。

### 稳定性

- 连续运行30分钟无重启、无看门狗复位、无持续闪屏。
- 快速连续触摸、滑动和状态切换100次无卡死。
- 设备断开串口后仍可独立运行。

### 可维护性

- 表情数据、动画引擎、硬件输入、绘制和诊断分层。
- 新增表情主要通过配置和关键帧完成，不复制大段渲染逻辑。
- 依赖锁定到具体版本或提交。
- 构建、烧录、验证和恢复命令形成文档。

### 安全

- 不写死 `COM5`。
- 不读取或修改 eFuse，不启用 Flash加密或安全启动。
- 未经再次确认不执行首次烧录、整片擦除或分区表变更。
- 完整 Flash备份不加入公开仓库。

## 7. 软件架构

```text
HardwareAdapter
  ├─ Display / Touch / Buttons
  ├─ BMI270 IMU
  ├─ M5IOE1 Vibration
  └─ Power diagnostics
          │
InputController ──> AvatarStateMachine ──> AnimationTimeline
                          │                       │
                          └──────────────> SpringEngine
                                                   │
GrokGeometryStore ──> AvatarRenderer <─────────────┘
                          │
                    DirtyRectPresenter

SerialControl / DiagnosticOverlay 作为旁路控制和观测层
```

- `HardwareAdapter`：StopWatch硬件初始化和原始数据。
- `InputController`：触摸手势、按钮、IMU滤波与事件去抖。
- `AvatarStateMachine`：基础状态、短暂反应、返回链和优先级。
- `AnimationTimeline`：关键帧、once/loop/pingpong和可中断过渡。
- `SpringEngine`：位置、旋转、缩放、眨眼和视线物理。
- `GrokGeometryStore`：生成后的眼睛、身体和调色板常量。
- `AvatarRenderer`：几何插值、裁切、灰阶边缘和绘制。
- `DirtyRectPresenter`：局部刷新区域合并和屏幕提交。
- `SerialControl`：调试命令及未来语义事件入口。
- `DiagnosticOverlay`：性能和外设可观测性。
