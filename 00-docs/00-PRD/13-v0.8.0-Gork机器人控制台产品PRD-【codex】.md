## 1. 产品决策

将现有 StopWatch 工作台升级为 Windows 上的 **Gork 机器人控制台**：统一桌面小人、语音交互、表情/气泡和 StopWatch 设备控制。沿用当前 UI 风格，不重建一个割裂的后台。

用户已经确认：

- 一个产品入口，桌面右下角的小助手与完整控制台配合使用。
- 合并语音功能的用户体验，不要求用户来回操作两个服务网页。
- StopWatch 优先播放设备内置声音，由电脑遥控；动态语音允许延迟接收、延迟播放。
- 本轮不以 StopWatch 实时对话为成功条件，不承诺 BLE 实时音频或五秒内回答。
- 本轮仅编制 PRD，后续由用户在另一任务中让 Sol 进入目标模式实施。

默认实施选择：Windows x64；保留 Python 工作台后端与独立语音引擎，以 Electron 增加控制台窗口、悬浮角色和托盘。一套业务状态驱动所有界面；网页仍作为可用回退入口。安装依赖前验证当前 Electron 稳定版本与宿主支持并锁定版本，不盲目升级既有 Python 环境。

## 3. 目标与非目标

### 必须交付

1. 一个双击入口打开控制台；托盘、悬浮小人、控制台共享状态。
2. 电脑端文字输入、按键录音、转写、朗读、停止与本地/云端语音选路。
3. 可接入的回答提供者接口；未配置时清楚显示“跟读/朗读”，不得伪造 AI 回复。
4. 桌面小人独立可用；设备离线不阻断电脑功能。
5. 同一程序管理 StopWatch 配对/连接、表情、气泡、内置声音和延迟音频任务。
6. 设备声音音量、静音、停止，明确与电脑系统音量分开。
7. 每阶段状态、进度、失败原因和可取消能力；模拟与真机验收分别记录。

### 本轮不做

- 不实现实时 BLE 耳机、唤醒词、全双工通话、Wi-Fi 音频、远程公网服务。
- 不自动执行电脑命令、读取屏幕、操纵其他应用；“控制桌面小人”不是电脑自动化代理。
- 不直接合并造价智算业务实现、不默认发送业务材料给模型。
- 不搬迁/删除原语音仓库，不复制模型、venv、密钥，不合并 Git 历史。
- 不默认开机启动、持续收音、自动重放历史音频、自动云上传或开多个设备连接。
- 不为内置音效修改分区、格式化文件系统或执行整片擦除。

## 4. 使用方式与模式

| 模式 | 输入 | 输出 | 用户预期 |
| --- | --- | --- | --- |
| 电脑交互（默认） | PC 麦克风或文字 | PC 扬声器；桌面小人表情；可选设备同步 | 正常交互主路径，不走 BLE 音频 |
| 设备本地声音 | 控制台选择 sound_id，可搭配表情/气泡 | StopWatch 播放 Flash 内置音频 | 只发短指令，无需每次上传 WAV |
| 延迟设备语音 | PC 文字/录音，或 StopWatch 按键录音 | ASR/可选回答/TTS 后传回 StopWatch | 明确显示传输和等待，允许数十秒延迟 |
| 测试/诊断 | 既有 tone、echo、record/play | 指定端 | 与主控制连接互斥，不冒充产品对话 |

语音来源、回答方式、播放端是独立选择，但同一轮只允许一个麦克风和一个播放端。切换任何路由先停止当前任务并作废旧结果；不得自动从设备扬声器切到电脑外放。离线时提示用户选择改用电脑。

默认“按住说话”或显式开始/结束；自动转写与自动朗读可单独启用，但不等于持续监听。StopWatch 录音首版仍要求进入 Audio test/明确的音频页后 ARM，再按 A；不得在表情主页后台偷偷启动麦克风。

## 5. 界面与桌面行为

### 5.1 沿用现有设计

来源：`03-Src/stopwatch-voice-companion/static/style.css`、`index.html`。
保留背景 #f3f2ee、正文 #20221f、深橄榄主按钮 #28301f、白色卡片、16 px 圆角、当前中文字体。品牌标题改为 Gork 机器人控制台；来源资产名称 Grok bot 保持原名，避免擅自改资产路径。

主窗口默认约 1180×820，允许缩放；小屏可滚动，不截断停止按钮。保留当前主面板+侧栏结构：主面板放对话/转写和录音操作，侧栏放角色、设备状态与音频路由。设置分语音、声音库、设备、桌面四组；诊断信息折叠，不堆满主界面。

- 顶部持续显示语音服务、设备连接、当前输入/输出、麦克风状态。
- 常驻“停止全部”；区分“取消传输”和“已确认停止播放”。
- 消息卡显示用户文字、回答来源、状态和本轮耗时；未配置回答者时标明跟读。
- 音效卡提供名称、时长、电脑试听、设备播放，两个按钮的播放端必须标清。
- 延迟任务显示真实阶段：录音→接收→识别→生成→合成→发送→播放，跳过的阶段标“不需要”。

### 5.2 桌面小人

首版提供透明、无边框的约 180–240 px 悬浮窗口，默认主屏右下角工作区内，避开任务栏；可拖动、缩放、隐藏、置顶开关。保存位置，显示器断开/分辨率变化后限制到可见工作区。

共用正式 Grok bot 资产快照；最少实现 idle/listening/thinking/happy/confused 及控制台选中的表情。能转换的来源时间轴应共享，禁止再做一套无法对应的任意表情。不得用浏览器 canvas 内一个角色冒充真正桌面悬浮窗口。

单击打开简洁对话面板，右键提供控制台、停止全部、隐藏、设置。文字气泡可折叠、可清除；桌面完整文字与设备 24 BMP 字符/72 UTF-8 字节限制分开处理。默认不抢输入焦点；不自动弹窗口打断用户工作。

托盘提供显示/隐藏、打开控制台、停止全部、设备连接状态、退出。关闭控制台默认收起至托盘，首次提示；退出会停止本程序音频并释放自有 BLE 会话。隐藏小人不等于退出、关闭控制台不等于允许后台录音；收起时若正在录音应停止并明确告知。

### 5.3 桌面安全与权限

Electron 渲染器禁用 Node 集成，开启 contextIsolation、sandbox，不关闭 webSecurity；preload 只暴露最小 IPC 白名单，不透传任意文件路径、命令或 URL。禁用任意导航/新窗口，外部链接经白名单交给系统浏览器。麦克风权限仅授予本应用可信本地来源并可撤回；不申请摄像头/屏幕录制。

参考（2026-09-21）：[Electron 窗口](https://www.electronjs.org/docs/latest/api/browser-window)、[安全指南](https://www.electronjs.org/docs/latest/tutorial/security)。这些支持选型，不替代本机透明窗口、麦克风和托盘实测。

## 6. 语音模块的“合并”边界

当前语音源码位于 `D:/Codex-Temp/260921-【语音】语音智能体模块`，服务默认 127.0.0.1:8765；当前控制台默认 127.0.0.1:8766。本机路径仅是交接定位，运行代码须用配置。

本轮合并的是入口、生命周期管理和设置 UI；引擎继续独立。控制台包含服务状态、配置路径引导、启动/连接、路由和授权，不要求打开 8765 网页才能日常使用。

- 用户首次选择受信任的语音服务目录及其独立 Python/启动入口。启动前验证入口、应用标识与健康接口；不搜索或读取 Key。
- 已有健康服务则复用；已有会话提示占用，只有用户明确“接管”才 replace=true。
- 服务未运行时，可启动用户已配置的实例，后台无额外可见终端。记录实例/PID/启动身份，不按进程名或端口杀进程。
- 退出只结束本程序启动且身份仍匹配的子进程；复用的外部服务不停止。先释放会话，避免中断其他已接管客户端。
- 未安装依赖/模型时给出准确安装步骤；不默认重复下载模型或改系统 Python。
- 沿用接口契约的 session/turn/request_id/generation 与两项上传许可；跨进程不是放宽访问控制的理由。前端不持有语音 Key，不开放任意 CORS。

若确实需要扩展语音服务接口，先在本仓库写缺口与契约版本，再请求语音项目修改；本执行包不授权平行改动外部仓库。现有完整 WAV 接口足够本轮延迟模式，不能假装 /v1/events 是 PCM 流。

## 7. 交互编排与回答来源

单一 Controller 管理 owner/session/turn/generation，桌面、网页、托盘和设备事件都走同一命令入口。多窗口只订阅同一状态，不各自创建语音会话/蓝牙连接；外部浏览器仍执行占用与接管规则。

状态机：idle → listening → receiving（设备输入时）→ transcribing → generating（有回答者时）→ synthesizing → sending（设备输出时）→ speaking → idle；任意阶段可 cancelling/error。表情映射复用已有实际目录；只有真实播放器启动回执才能进入 speaking。

回答提供者：首版实现可配置的 OpenAI-compatible 文本接口适配器，配置 base_url/model/独立凭据来源，不指定付费供应商或复用语音 Key。不配置时启用“跟读/朗读”模式，禁用“AI 对话”并给明确说明。配置和上传许可齐备后才可真实调用。

文字发送给回答服务有独立“允许向回答服务发送文本”开关，不与 ASR/TTS 权限混用。本地回环提供者也须明确地址；云端默认不发送历史文件/屏幕/业务数据。首版短文本、有限轮历史，仅内存保存，支持清空；无工具调用。造价智算只预留适配接口，本轮不接真实业务。

回复超出 TTS 300 字限制时按句分段或提示，不默默截断；设备单段音频最多 10 秒/现有缓冲上限，超限明确拒绝并建议电脑播放，不承诺多段无缝设备播报。网络重试不得重复播放、重复扣费；断线后不补播旧任务。

## 8. StopWatch 内置声音：本轮硬件重点

### 8.1 资产与存储

首版至少 6 个短提示音：ready、confirm、thinking、success、error、goodbye；每段 0.15–1.0 秒，总时长不超过 4 秒。可采用可再分发现成音效，必须附来源/许可；没有合适资产时允许原创合成非语言提示音作为完整首发库，不用无来源素材凑数。暂不要求预录中文人声。

统一 16 kHz、PCM16、单声道，去直流、控制峰值、首尾短淡入淡出。使用确定性转换脚本和 manifest（id、名称、时长、采样率、字节数、来源、许可、默认音量）。保留源文件，生成 C++ const 数组编入应用 Flash，总 PCM 不超过 128,000 bytes。首次转换不能覆盖用户原始音频。

这样不占用/格式化未知文件系统，也不改分区。新增声音需重新构建且烧录需当次授权。用户自定义上传、无线更新声音库列后续，不混入首版。

### 8.2 控制协议

独立声音控制服务/特征或现有受保护服务内明确的新命令均可，但 Sol 必须先落协议文件再编码；优先新增版本化控制特征，保留旧 UUID/20-byte 表情与文字协议。控制包保证 20-byte MTU 下可用。

必备操作：capabilities/catalog version、play(sound_id, request_id)、stop(request_id)、set_volume(0..100)、get_status。参数有界，未知 ID/协议/忙态拒绝，不接受任意路径、未验证音频数据或来自未绑定端的命令。

回执至少包含本连接有效的 request_id、accepted/started/completed/stopped/failed 和错误码；重复同一请求不重复出声。去重缓存有界且连接重置；超时显示“未确认”，不自动重试 play。所有通知只发给授权连接，不广播敏感状态。

电脑只下发短指令，设备主循环调用播放器，BLE 回调不做 I2S 或堆内存操作。固件统一音频所有权：内置声音、测试音、录音、动态 PCM 互斥。录音或传输中收到 play 返回 BUSY；停止具有最高优先级；第二个播放不排长队，首版 BUSY 即可。

设备保留表情动画，声音功能不能强制停留测试页才能使用；仅录音仍受页面+按键限制。音频播放时 B 优先停止、消费该按键，不同时切表情；无音频时原 A/B 行为保持。Settings 内 B 的停止优先规则同样适用。

### 8.3 音量与停止

设备 Settings 新增 Sound：0–100、步长 5、静音开关、短试听（仅显式点击）。默认约 20%，映射为库 0–255 并夹紧；0 保证静音。静音保留上次非零音量；NVS 延迟写入/退出设置提交，避免每次拖动写 Flash。控制台显示设备回执值，电脑音量单独设置。

遥控播放时蓝牙断开停止；停止先停实际音频任务，再释放资源、发停止回执。主界面显示“请求停止”与“设备已停止”区别；设备无响应时提示按 B，不能假称已静音。退出、切模式、取消均不得重播未结束声音。

## 9. 延迟语音模式

保留并整合现有 v0.7.2 音频工具，不再让用户另开占用 BLE 的命令行。设备输入或输出任一被选择时，显著显示“延迟模式，非实时，可能等待数十秒”；若设备音频页未开启，提供操作指引，不偷偷开始采集。

每次传输显示已收/已发字节、总字节、百分比、阶段耗时和实测速度；估算剩余时间只在足够样本后显示，注明估算。录音未结束时总长度未知，只显示已录时长/字节。禁止假进度和无状态等待。

进度按累计有效字节计算；只有匹配回执才推进。大音频先估算传输开销，超限拒绝，不无限排队。取消控制可越过音频数据队列，并清空旧 generation。设备离线及时失败，重连不继续旧录音/播放，私人 PCM 默认内存持有，失败/取消/完成释放。

本轮可以保留信用窗口 1，只要延迟可见、取消可靠；批量确认/压缩/流式音频是后续性能版本，不得为追吞吐削弱绑定/加密/校验。共享一个 BleakClient 和连接管理器发现所需表情、声音、音频服务；不能启动第二个控制器争抢。已有 Windows 定向无缓存发现行为需回归，不能简单改成全服务 UNCACHED 并忽略 0x8000FFFF。

| A5 | 设备声音库 | 6 声音逐项真机听验，30 次顺序控制无重复/错播；已连接时命令到 started 回执 P95≤500 ms，起音听感单独确认 |
| A6 | 音量/停止 | 0 静音、调节可听、重启保持；20 次 B/遥控停止，目标≤300 ms，超标记问题不伪报 |
| A7 | 延迟模式 | PC→设备、设备→PC、设备→处理→设备分别测短音频；每阶段有进度，取消后无迟到播放 |
| A8 | 安全/权限 | 未绑定端不能播放/调音量/启动录音；云权限关闭无请求；三类上传授权互不替代 |
| A9 | 回归 | 旧 65 项测试、6 计时断言保留；表情/气泡/happy-work、设置、音频页和重连回归；构建通过 |
| A10 | 稳定性 | 桌面待机 30 分钟、10 次断连重连、20 次各阶段取消，无持续内存增长/旧结果播放；记录资源消耗 |

PC 问答以“结束说话→首个可听回复”分解 ASR、回答、TTS、播放耗时；约 5 秒是体验方向，依赖真实提供者，不作为设备延迟模式硬指标。不把 Mock、HTTP 200 或播放完成通知等同听到声音。
