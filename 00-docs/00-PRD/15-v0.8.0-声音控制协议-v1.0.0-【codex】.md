# v0.8.0 StopWatch 声音控制协议 v1.0.0

> 状态：设计冻结，固件与客户端实现待完成。本文不代表设备已升级。

## 1. 边界

- 新增独立 BLE 服务，不修改 v0.3.0 表情/文字 UUID，也不修改 v0.7.2 音频探针 UUID。
- 所有特征均要求加密；应用层继续只接受本机已绑定控制端。状态通知必须定向发送当前授权连接。
- 控制包在 20-byte ATT payload 下完整工作；BLE 回调只校验并排队，播放器和 NVS 均由主循环操作。
- 音频所有权只有 `idle / builtin / probe-record / probe-play / dynamic-play` 五种状态；同一时刻只能有一个非 idle 所有者。

## 2. UUID 与帧

- Service：`48f1c001-8a75-4db6-9c18-590f7e9b0a01`
- Command：`48f1c002-8a75-4db6-9c18-590f7e9b0a01`，加密 write-with-response
- Event：`48f1c003-8a75-4db6-9c18-590f7e9b0a01`，加密 read/notify

小端二进制帧：`version:u8, op:u8, request_id:u16, value:u32, arg:u8`，固定 9 字节。版本为 1，request_id 必须非零。

| op | 请求 | value | arg |
| --- | --- | --- | --- |
| `0x01` | capabilities | 0 | 0 |
| `0x02` | catalog | 0 | 0 |
| `0x03` | play | 0 | sound_id |
| `0x04` | stop | 0 | 0 |
| `0x05` | set_volume | 0..100 | 0 |
| `0x06` | get_status | 0 | 0 |

事件沿用同一头部，op 为 `accepted 0x80 / started 0x81 / completed 0x82 / stopped 0x83 / status 0x84 / failed 0xff`。`value` 表示能力位、当前音量或错误码，`arg` 表示声音 ID/当前所有者。

## 3. 规则

- 六个声音固定 ID：1 ready、2 confirm、3 thinking、4 success、5 error、6 goodbye；未知 ID 返回 `UNKNOWN_SOUND`。
- 同一连接内缓存最近 8 个 request_id 及终态；重复 play 返回原状态，不再次发声。断连清空缓存。
- 播放忙时不排长队，返回 `BUSY`；stop 具有最高优先级并可越过普通命令队列。
- 音量范围 0–100、步长 5；设备映射到 0–255。静音保留最后一个非零音量。NVS 只在退出设置或 800 ms 无调整后写入。
- BLE 断开立即停止声音。未收到匹配 request_id 终态时，电脑显示“未确认”，不自动重试 play。

## 4. 音频资产

统一 16 kHz、PCM16、单声道、首尾淡入淡出，总 PCM 不超过 128,000 bytes。`01-assets/audio/manifest.json` 是声音 ID、时长、字节数、来源和许可的权威清单；生成文件不得覆盖源素材。

## 5. 验证门禁

协议单元测试、资产验证、固件构建通过只证明静态/构建层。未获当次烧录授权不得写设备；六声音、静音、音量保持、B 键停止、断连停止和未绑定端拒绝均需真机另验。
