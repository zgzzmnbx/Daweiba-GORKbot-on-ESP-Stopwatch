# v0.19.2 / v0.19.3 自定义表情库与编辑保存

用户最新要求：可选择已有自定义表情、调整并保存；自定义表情加入菜单；默认表情不得被修改。用户另要求立即恢复待机等默认动画。本要求覆盖交接提示词与 v0.19.0 中共享配置保存后即时覆盖桌面行为。

## 实现与使用

1. 编辑器“编辑对象”仅列出自定义表情和“新建自定义表情”，不将 23 个内置表情作为可写对象。
2. 选择已有条目读取其完整参数、名称和动作场景，调整后“保存修改”更新该 ID，不创建重复条目。
3. 新建或“另存为新表情”产生独立 ID；另存同名时自动生成递增副本名称，保留原条目；普通保存的重名和并发修订冲突明确报错。编辑器显示已保存数量，上限 64 个。每个条目含四场景配置及一个选定播放场景。
4. 保存只写独立库，通知父页重新读取菜单；不发送播放 IPC、BLE 或角色请求。播放时复制配置快照，之后保存不能改变该快照。
5. 左侧菜单保留 23 个原始表情，并追加带“自定义”标记的命名条目；悬停只预览，点击才播放。一次播放返回原版 idle，循环直到显式切换。角色下拉同样列出自定义条目。
6. 默认待机和其他旧表情始终调用原版 GorkAvatar，无论表情库如何保存。交接包原值及旧 motion.local.json 只作新建草稿来源。

## 数据与接口

正式文件 `03-Src/stopwatch-voice-companion/motion-library.local.json`，schema=gork-expression-library/version=1，最多 64 个。条目为 id/name/scene/config，ID 为 motion- 加 12 位十六进制，名称 1–48 字符。文件原子替换、有效备份 .bak、修订 CAS；读取失败禁用保存，原文件保留。两个文件都损坏时需人工从备份恢复，不以空库覆盖。

- GET /api/motion/expressions：读取库；GET /{id}：读取条目。
- POST /api/motion/expressions：新建；PUT /{id}：仅更新已有自定义 ID。精确字段 name/scene/config/expected_revision，流式上限 24 KiB，配置继续严格验证。
- 旧 PUT /api/motion/config 和 POST /config/recover 返回 409；旧 GET 保留作为草稿参数来源。
- /api/character 沿用工作台控制权；桌面接受保存的自定义 ID，Watch/两端拒绝该 ID。
- 导出 Watch 参数要求 expression_id，读取该条目的已保存参数；没有运行时下发，本轮不修改固件。

## 验收

保存新条目和修改旧条目时，默认数据及角色播放状态不变；修改只影响一个 ID；另存保留原 ID；菜单可见且显式播放使用最新保存参数；当前播放使用旧快照；重载后条目仍在；默认 idle 回原版，生命周期保持单一 RAF。自动检查与真实 Windows Electron 结果见本版报告。Watch 实屏/帧率/BLE 与状态标签拖动人工验收不包含在本版自动结论中。

## v0.19.3 播放与多副本补验

显式点击自定义表情播放完整动作，即使系统减少动态效果开启；编辑器初始预览仍跟随系统，内置表情保持原规则。桌面 IPC 的 requestId 随成功播放状态回传，同一 ACK 回传不得重复挂载，新播放请求及全新渲染进程仍正常启动。控制台生成页保留源码完整脚本顺序。

验收同时比较控制台与桌面连续帧像素，验证循环持续运动、一次结束返回原版 idle、每次点击只挂载一次；另存同名至少连续生成两个副本，三个条目重新选择及重载后仍独立存在。结果见 `04-output/v0.19.3/自定义表情播放与多副本保存验收-【codex】.md`。此前 v0.19.2 保存/回执验收不能代替本次持续运动验证。

## v0.19.4 书写范围

用户截图中的五项参数扩大为：整体水平 −160～160、整体垂直 −120～200、笔迹整体大小 0.25～2.5、笔的大小 0.25～3、笔迹粗细 0.5～12；各步长仍为 1、1、0.05、0.05、0.25。其余参数与旧存储 schema/version 保持。现有合法条目不迁移、不重写，不改默认配置。

浏览器/后端范围相同，桌面可播放保存的新值；Watch 导出的保存参数与 C++ minimum/maximum 一并更新，仅导出，不改已编译候选或设备。新尺寸可能触发脸部裁剪，位置继续使用现有圆形安全约束。边界保存/读取、旧参数保持、连续动作及导出验证见 v0.19.4 验收记录。
