# 语音模块复用边界与接口验收

> 文档版本 v1.0.0｜2026-09-23｜状态：架构核查与下一轮要求，非本轮代码实现。
> 用户追加要求：语音识别和播放保持模块化，以后可供其他程序复用或通过接口调用。本文件是 [PRD 16](16-v0.9.0-Gork控制台界面重组PRD-【codex】.md) 和 [Goal 任务书 17](17-v0.9.0-Goal模式执行任务书-【codex】.md) 的强制补充。

## 1. 现在到底是什么关系

已核对任务“初始化本地语音模块项目”（`01a0bec3-7a83-7711-bd10-0eecf4ef07c1`）的交接记录，以及两个仓库的当前源码。

结论：**Gork 接入并复用了那个任务开发的独立语音服务，不是把识别/合成引擎移植进 Gork 后变成私有副本。**

| 部分 | 当前归属与证据 | 复用方式 |
| --- | --- | --- |
| 本地/云端识别、语音合成、音色目录、服务请求取消 | 独立语音仓库 `03-Src/voice_service/app.py`、`broker.py` | HTTP `/v1/*`，可独立运行 |
| Gork 的语音 HTTP 适配器 | `03-Src/stopwatch-voice-companion/companion/voice.py` 的 `VoiceClient` | 仅 httpx + 标准库，不导入引擎/模型/蓝牙 |
| 电脑麦克风采集、WAV 转换、扬声器播放 | `static/app.js`、`pcm.js` | 当前部分逻辑耦合页面，需要提取 |
| 表情、气泡、回答流程、设备音频路径 | Gork 的 Controller、Robot 与 Electron | 产品编排，不属于通用 ASR/TTS |
| 启停独立语音进程 | `service_manager.py` 与可配置托管入口 | 管进程，不把引擎代码并入 Gork |

语音服务 `capabilities` 明确不提供业务回答或设备音频控制。TTS 返回完整 `audio/wav` 字节，**不是命令服务器电脑或 StopWatch 自动出声**；播放在哪台设备发生，由调用方决定。

## 2. 目标模块划分与依赖方向

```text
Gork / 造价智算 / 其他程序
  ├─ 各自界面与业务逻辑
  ├─ 客户端音频模块：采集、WAV、播放、立即停止
  └─ HTTP 客户端
           ↓ 可配置地址，版本化 /v1 接口
独立语音服务：会话、能力目录、ASR、TTS、取消
  └─ 本地模型适配 / 云端适配 / 服务侧凭据

Gork 另外管理：角色、BLE、StopWatch、桌面窗口、可选 AI 回答。
独立语音服务不反向依赖以上 Gork 模块。
```

四层必须分开：

1. **语音引擎层**：继续由原语音仓库维护，不为 Gork 复制另一套模型/供应商代码。
2. **HTTP 客户端层**：只收发服务协议；不读取页面 DOM、不操作 BLE/桌面、不直接访问 Key/模型目录。当前 `VoiceClient` 可继续复用，不为“模块化”重建 SDK 仓库或发布包。
3. **客户端音频层**：浏览器采集与播放独立 ES module，接受回调/依赖，不导入 Gork 页面、角色、设备或回答模块。适用于网页/Electron 渲染环境；其他语言程序可自选播放库。
4. **Gork 编排层**：决定何时识别、何时问答、何时朗读和显示表情；负责 generation 与目标设备，不把产品状态塞进语音服务。

“其他程序可调用”首先指同一电脑上的本地服务。当前默认绑定 loopback，并有跨源限制；不因本需求开放局域网监听、通配 CORS 或公网接口。其他网页应由它自己的后端代理调用，桌面/Python/.NET 等可由程序后端直接 HTTP 调用。

## 3. 已有 HTTP 契约摘要

当前核对基线：服务 v0.3.2、`protocol_version=1`。默认地址 `http://127.0.0.1:8765`，接入程序通过配置覆盖，不在通用模块写死本机路径。

| 方法/路径 | 用途与关键约束 |
| --- | --- |
| `GET /v1/health` | 服务存活、版本、模型状态；ready 不是云额度或真实发声证明 |
| `GET /v1/capabilities` | 协议版本、音色/格式/长度等能力；不要依赖硬编码目录 |
| `POST /v1/sessions` | `{replace:false}` 获取 session_id；占用时 409，不默认抢占 |
| `PATCH /v1/settings` | 会话头；完整提交 asr/tts/allow_audio_upload/allow_text_upload |
| `POST /v1/sessions/{session_id}/turns` | 会话头；创建 turn_id，上一轮未完成请求取消 |
| `POST /v1/asr/transcribe` | 会话头；multipart request_id、turn_id、audio；文本位于 `result.text` |
| `POST /v1/tts/synthesize` | 会话头；JSON request_id、turn_id、text、speaker_id、speed、sample_rate；按能力可选 cloud_voice；返回完整 WAV |
| `GET /v1/requests/{request_id}` | 会话头；查询状态和错误，不返回合成音频字节 |
| `POST /v1/requests/{request_id}/cancel` | 会话头；JSON turn_id；不等于客户端扬声器已经静音 |
| `DELETE /v1/sessions/{session_id}` | 会话头；释放自身会话和缓存 |

会话头为 `X-Voice-Session`，不是 Gork 的 `X-Companion-Client`；两者必须分别处理。Token 不入 URL、日志、截图或 Git。

ASR 当前接受 PCM16 单声道 16 kHz WAV，默认 0.1–30 秒、≤2 MiB；TTS 当前默认最大 300 字符、WAV 输出 16/24 kHz。上限以运行服务能力及校验为准，不通过改扩展名把 WebM 冒充 WAV。

调用顺序：探测 → 取得会话 → 明确设置本地/云端和许可 → 创建 turn → ASR 或 TTS → 消费文本/WAV → 释放。ASR/TTS 可以分别调用，不要求先创建 Gork、连接 Watch 或调用 AI 回答。

每请求使用独立 request_id；保留 session/turn/request 层级与客户端 generation。停止先在调用方静音，再取消服务请求，并丢弃迟到音频；服务取消不能物理终止所有已在客户端排队的声音。

旧的 `00-docs/02-交接/StopWatch-语音服务接口契约-v1.0.0-【codex】.md` 是 v0.3.1 历史冻结副本，其中“云端固定 Cherry”已被 v0.3.2 能力目录扩展替代。不要据旧文档删掉现有选声功能。实际 API 以当前源码/OpenAPI 为准；本文件不是偷偷修改外部服务的授权。

## 4. 多程序复用不等于同时无限并发

当前服务只有一个活跃控制会话。Gork 与其他程序可分别复用，但不能各自默认 replace=true 抢来抢去。

- 其他程序调用时若服务被 Gork 占用，提示使用方释放；只有明确接管操作才能替换会话。
- Gork 的工作台控制权和语音服务会话分离：用户可以释放语音会话，让其他程序使用，同时继续控制桌面/Watch。
- 新设置页提供“释放语音会话”动作及占用状态；不得把它等同退出整个 Gork 工作台。进行中的语音任务须先取消。
- 接管失效后 Gork 停止本地音频、丢弃旧结果，不自动抢回；用户下一次明确语音操作才尝试重新连接，仍先 replace=false。
- 服务已由其他程序启动时可复用，但 Gork 退出不得杀掉它。服务由 Gork 托管时，其退出可能让其他调用者失去连接；本轮说明这一生命周期限制。跨程序长期共享建议使用独立启动入口，不能承诺目前托管器已有跨应用引用计数。
- 多租户、服务端并行会话、跨电脑服务、安全认证和共享守护进程是后续独立版本，不纳入此次界面优化。

## 5. v0.9.0 必须落实的最小代码要求

### 5.1 HTTP 客户端

保留独立 `VoiceClient`（或等价薄适配器）的输入/输出边界，允许注入 base_url、timeout、测试 transport。不导入 Controller/Robot/Electron，不反向 import 外部语音源码，不直接读取外部配置/凭据。

错误、格式检查、能力不兼容、会话占用/失效、请求取消均由客户端明确表达，由产品层决定如何显示。不能自动“遇到本地失败就上传云端”，也不能自动重试可能重复计费的请求。

### 5.2 客户端音频模块

建议新增 `static/audio.js`，复用 `pcm.js`；具体类名可调整，但至少具备：

- Recorder：显式 start、finish（返回合法 WAV）、cancel、dispose；能释放 MediaStream tracks 和音频资源，超时/失焦由上层事件触发结束。
- Player：playWav、stop、dispose，及 started/ended/error 通知；只接受合法完整 WAV，播放前确认用户手势/浏览器权限。
- 生命周期幂等：重复 stop/dispose 不抛未处理异常；取消之后迟到的 getUserMedia/decode 结果不会重新开麦或播放。
- 不在模块初始化/import 时开麦、播放、发请求或读 DOM；不内置语音云 Key、BLE、表情或 HTTP 服务地址。
- 单个 Gork 界面的对话 TTS、音色试听、内置声音电脑试听和设备返回 WAV 共用音频仲裁，不能提取后变成四个各自出声的播放器。

模块只负责音频资源；Gork generation/业务状态通过回调或取消信号协调，不复制第二套互相竞争的业务状态机。

### 5.3 接口使用示例与文档

执行阶段新增 `tools/examples/voice_service_http_example.py`（或等价无机器人依赖的简单脚本）：

- 默认只做 health/capabilities 探测，不自动开麦/播放/云请求。
- 提供明确的 TTS 文本→用户指定 WAV 文件，及 ASR 用户指定 WAV→文字两条独立命令；本地路由、上传许可 false、replace=false。
- 输入/输出均显式指定，输出文件已存在时不默认覆盖；不把声音示例产物写入 Git。
- 用标准 HTTP/httpx 调用 `/v1/*`，不导入 Gork app、BLE、Electron 或模型；这是使用示例，不是复制一整套引擎或维护第二个生产客户端。
- finally 释放自己成功取得的会话；失败不释放其他程序会话，不打印会话 token；占用、服务离线、格式错误均有清楚提示。
- 不新增第三套 venv。示例依赖和运行命令写入 `04-output/v0.9.0/语音模块接入说明-【codex】.md`，说明 Python/.NET/其他后端只要遵守 HTTP 契约即可接入。

接入说明应包含模块边界、请求/响应示例、能力查询、选声、取消、会话占用、显式上传许可、播放端职责及本机跨源限制。不要把 Key/机器绝对路径嵌进可复制代码。

## 6. 新增强制验收

| ID | 用例 | 通过条件 |
| --- | --- | --- |
| V01 | 依赖隔离 | VoiceClient 及 audio 模块不依赖 Gork 角色/BLE/页面；语音引擎没有复制进本仓库 |
| V02 | 独立 HTTP 消费者 | 示例可在 Gork 后端/Electron 未启动、Watch 未连接时获取能力并调用本地 TTS；记录真实 WAV 格式，不自动播放 |
| V03 | 独立 ASR | 用显式的合成测试 WAV 或用户授权样本调用；请求可完成，识别内容/音质验收单列；无真实环境偷录 |
| V04 | 不带界面的音频单测 | 通过注入浏览器音频依赖覆盖 start/finish/cancel、播放/停止、资源释放、迟到结果；无需 Gork DOM 或 BLE |
| V05 | 多消费者互斥 | Gork 占用时第二客户端收到 409；释放语音后第二端可用；Gork 的角色/设备控制权仍在 |
| V06 | 外部接管/停止 | 旧端立即停止本地输出、迟到结果失效，不自动抢回或播放旧 WAV |
| V07 | 版本与能力兼容 | 旧服务默认音色降级、新服务目录正常；不兼容 protocol 明确拒绝 |
| V08 | 无副作用默认行为 | 导入模块/打开页面/运行示例默认探测不录音、不播放、不发云请求；模块取消测试通过 |

V02/V03 在可用的隔离本地服务上执行，使用合成非私人内容。若无法启动隔离服务，不擅自抢占现有会话，记录具体阻塞；只有 mock 不能宣称独立端到端复用已验收。代码交付与运行验收分别标记。

本文件只定义本仓库的最小提取、接入示例与验收，不要求本轮改独立语音仓库。发现服务接口问题，交接给原语音模块项目维护，防止在 Gork 内绕过接口另写一套。
