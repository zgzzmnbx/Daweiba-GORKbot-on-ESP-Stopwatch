# Gork 单页自适应工作台设计规划

文档版本：v1.0.3｜日期：2026-09-23｜状态：设计与交互原型，正式程序尚未实施。

建议目标版本：电脑端 v0.10.0-dev；当前正式源码仍为 v0.9.0-dev，语音服务 v0.3.2，设备 v0.8.6-dev。本次不提升运行程序版本、不生成新发行包、不提交既有脏树。

## 1. 最新用户要求与设计决定

用户要求页面下沿随窗口高度适配，不要整页滚动；随后明确指出“桌面角色 · 语音 · 设备 / Gork 机器人控制台。/ 对话、角色、StopWatch 和设置各归其位。”占用过多空间，希望一页使用或进一步优化。

最新用户看过 v1.0.2 后明确要求回到 **左侧常驻机器人，右侧对话与其他功能按标签页切换**。当前方案为左右双栏常驻布局：左侧约四成展示持续动画机器人；右侧约六成，顶部是“对话 / 角色 / StopWatch / 设置”，下方显示当前模块。v1.0.2 上方头像、v1.0.1 侧滑面板均不再采用。

- 顶部工具栏仅保留 GORK、语音/设备状态与停止全部，不重复放模块入口；不恢复三行大介绍。
- 左侧机器人处于所有模块之外的共享区域，切换标签不隐藏、不重建、不重启动画。
- 右侧菜单固定在内容上方；点击只切换右侧模块，不出现遮罩、侧滑弹层或独立页面。
- 整体内容最大宽度约 1160 px，按约 4:6 分配角色/内容，避免聊天框铺满宽屏。
- 对话草稿、消息位置、设置草稿保留；切换不重新连接服务或设备。正在录音时按既有结束规则处理。
- 标签使用 tablist/tab/tabpanel，支持左右方向键及 Home/End；Tab 正常进入内容，不使用弹窗焦点锁。
- 角色模块点选表情直接在左侧机器人本地预览；发送到桌面或设备仍需独立点击。
- 输入与各模块底部主要操作保持可达，内容过多只在内部滚动。正常桌面无整页横纵滚动。
- 只有 ≤680 px 的窄窗口才把常驻机器人收成顶部紧凑伙伴区；普通桌面始终保持左侧布局。

用户随后追加两项要求，已并入当前 v1.0.3 原型：机器人下方显示状态和开关；**默认云端朗读**。

- 左侧机器人下方增加紧凑状态面板：语音准备/连接状态、StopWatch 连接状态、当前已应用朗读方式；不显示协议未提供的电量等假数据。
- 快捷开关为“自动朗读 / 表情联动 / 桌面小人”，另提供详细设置入口；其中桌面小人开关只影响独立桌面窗口，不隐藏页面常驻机器人。正式网页无桌面桥接时该项需标记仅桌面端可用。
- 自动朗读只决定 AI 回答后是否自动播放，不影响手动朗读；表情联动关闭时停止自动业务表情，手动预览仍可使用。原型只演示本地状态与提示，不修改真实服务或桌面窗口。
- 初次无已保存偏好时：语音识别默认本地，文字朗读默认云端；已有明确保存的选择及许可撤销值继续保留。用户本次指定的是默认值，不据此覆盖已有个人偏好。
- 默认云端不等于自动发送；输入明确提交或试听后才请求合成，仍要求上传文字许可。云端不可用时就地说明并提供切换本地选项，不静默降级或伪报成功。
- 音色及语速遵循服务 capabilities；当前云端只开放自然 1.0×。原型使用明确标注的云端默认示例音色，不冒充真实能力目录。

## 2. 现状与实际缺口

2026-09-23 检查当前 8766 页面与 static/index.html、style.css、app.js：

1. 页面顶部介绍与角色占用大段高度；约 1346×986 的浏览器视口中，朗读按钮 top 约 981 px，已落到首屏外。
2. body 由内容撑高，main 使用大间距，没有完整的视口高度分配；顶部停止随整页滚动离开视野。
3. 首页只提示连接，真实连接入口在设置页；角色页又依赖设备页的取得控制权入口。
4. 多页操作调用统一 message()，但消息节点位于对话页，导致其他页错误不可见。
5. AI 回答覆盖 transcript 原输入，没有独立的可见问答记录。
6. 按住说话同时绑定 click/pointerdown，录音后隐藏原按钮；存在操作语义和结束路径问题，不能只改文案。
7. scan、sound-play、sound-volume 的 render 禁用条件仍使用 connected（语音会话），与已设计的工作台控制权解耦不一致。
8. 应用并保存与应用音色调用同一个 apply()；改音色造成 dirty 后，主输入禁用而原因远离用户。

上述是本次静态和页面检查事实，不代表已执行设备/麦克风故障复现。

## 3. 主界面布局

```text
┌ GORK        语音状态 / 设备状态                 ■停止全部 ┐
│ 桌面伙伴                 对话  角色  StopWatch  设置     │
│                         ┌─────────────────────────────┐│
│      动画机器人         │ 当前标签页内容              ││
│      始终在左侧         │ 对话 / 表情气泡 / 设备 / 设置││
│                         │ 内容较多时内部滚动          ││
│         Gork            │                             ││
│       当前状态          ├─────────────────────────────┤│
│  [打个招呼] [换表情]    │ 输入与发送 / 播放 / 连接等 ││
│                         └─────────────────────────────┘│
└──────────────────── 简短状态 ──────────────────────────┘
```

常驻机器人沿用正式 catalog 与共用渲染器，idle 持续播放；正式版根据录音/识别/回答/播放阶段切换相应动画。桌面头像约 190–285 px，较矮窗口约 210 px。窄窗口的紧凑伙伴区高约 70–94 px、头像约 64–86 px。原型“打个招呼”播放 happy 一次后返回待机；“换个表情”切换右侧角色标签。角色标签共用左侧头像做本地预览，不再摆第二个头像；只有显式提交才操作桌面或设备。

### 3.1 高度与滚动规则

- 应用根：height:100dvh，兼容回退 100vh；grid-template-rows:auto minmax(0,1fr) auto。html/body 高度 100%、overflow:hidden。
- 所有处在可收缩链路的 grid/flex 容器必须 min-height:0、min-width:0；只给根加 overflow:hidden 不合格。
- 会话区：工作区为左侧共享机器人与右侧可收缩标签页，右侧内部为标签栏/模块内容；聊天内消息区 minmax(0,1fr)、输入区 auto；消息长了才出现内部滚动。输入超过可见行数时仅文本框内部滚动，不无限撑高。
- 模块区：标签栏 auto、模块内容 minmax(0,1fr)、模块操作栏 auto；设置内容独立滚动，保存按钮固定在内容区下沿。
- 控件与文字不能通过 transform:scale 或强行缩小字体来塞入视口；不使用隐藏滚动条掩盖不可达内容。
- 长文本设置 overflow-wrap:anywhere；列表及表单允许换行，无横向溢出。
- 正常桌面建议视口至少 960×600；主要验收包括 1180×820、1366×768、1024×600、820×600、390×700，另测 390×540 与 200% 等效缩放视口。
- 宽度 ≤820：压缩顶部设备摘要；≤680：机器人收成紧凑伙伴上行、四个标签占下一行，设置分类改横向选择，保留文字标签。
- 高度 ≤650：减少空白与输入行数；极端高度 ≤420：工作区/面板允许内部整区滚动以确保所有控件可达，此时不承诺输入区始终固定。仍不让 body 撑高。正式 Electron 可评估 minWidth 800/minHeight 560，须结合缩放和多屏可用区域验证，不能只靠限制窗口掩盖布局问题。
- 移动软键盘：100dvh 为基础，实际环境需要验证 visualViewport 与输入焦点，必要时调整工作区可用高度；桌面浏览器模拟窄屏不等于手机键盘验收。

### 3.2 对话操作

- 未准备：主按钮“开始使用”，点击后按需启动/复用服务、申请空闲控制权、建立语音会话。已有占用才弹出说明和明确接管，不自动夺取。
- 正在准备：阶段提示与取消入口，防重复提交；准备完成后回到可输入状态，不自动发送已有草稿。
- 默认朗读模式；AI 配置缺失时不可选，并在设置模块提供说明。不能以预置文本冒充真实 AI。
- 点击录音开始，按钮原位变为结束录音，显示时长与收音状态；再次点击结束。首版不再混用按住操作。最长 30 秒，失焦/关闭/切面板时按约定结束或取消并明确反馈。
- 识别文字先进入草稿，用户编辑确认后才发送；不自动上传给 AI。
- Enter 发送、Shift+Enter 换行，中文输入法组合期间不发送；点击和快捷键共享相同禁用/忙碌校验。
- 发送后新增用户消息，AI 回复另建结果消息；TTS 失败不丢失回答；可以重试朗读该条回答，不重复生成 AI 回答。
- 保留既有 300 字请求限制；长回答完整可见，超过语音接口上限时解释限制，不静默截断或擅自增加分段合成范围。
- 新会话清除可见消息和服务端上下文；失败须说明结果，不能只清前端后声称两端完成。
- 记录只在当前会话内存，不保存私人输入、录音、回答到 localStorage 或磁盘。刷新后的恢复不在本轮范围。
- 用户已向上回看时新消息不抢滚动位置，显示“有新消息”；贴近底部时自动跟随。

## 4. 三个功能模块

### 4.1 角色

- 正式来源角色单个动画在左侧共享机器人预览；中文常用表情网格，完整 24 项可搜索/分组，英文协议名只在诊断显示。
- 点选仅预览；发送目标、单次/循环与提交在同一区域，底部固定“恢复自动联动 / 播放到目标”。
- 气泡编辑区就地注明目标、字数与 Watch 字节限制；目标沿用角色选择并在气泡旁重复摘要，避免含糊。
- happy-work 仅 Watch；本机预览展示“设备专属”说明，不伪装成有纸笔层。
- 当前占用、目标离线、不支持、部分完成都在面板内反馈；电脑预览不申请设备控制权。
- 桌面窗口显示/隐藏/位置恢复等能力只有桥接存在才可用，不创建虚假按钮。

### 4.2 设备

- 日常区只含连接状态、六个声音、播放端选择、音量。
- “连接设备”内部完成必要空闲控制权申请，再进入本次扫描列表供用户选择；不能依据历史地址自动挑选并写入设备。
- 设备扫描/声音/音量只依赖工作台和设备状态，不依赖语音在线；需要识别或合成的实验路径才申请语音会话。
- 播放端明确为电脑试听/设备播放，点击音效执行对应端；未连接设备时给予连接入口。
- 音量未读取时显示“未读取”；只把设备确认的提交值当作已设置，不伪造当前值。
- 实验功能改为面板内子页，替代越展开越长的主页面；文字输入就在实验页，不跨页借用隐藏 transcript。
- 保留三条实验路径及准确语义：电脑合成→设备；设备录音→电脑直接回放；设备录音→识别/可选回答/合成→设备。
- 实验运行中即使切换模块，顶部仍有阶段与取消入口；停止未确认与电脑已静音分开显示。

### 4.3 设置

- 四个类别：语音与音色 / AI 回答 / 隐私许可 / 服务与诊断；设置模块一次只看一类。
- 识别、朗读路由、音色、语速集中；合并“应用并保存 / 应用音色”为底部一个“保存设置”。
- 默认本地识别、云端朗读；左侧朗读方式摘要显示已应用值，设置草稿未保存时不提前改变摘要。
- 保存的是下一次请求偏好；未保存草稿不使整个对话页突然失效，仍可使用上一份已应用设置。若服务接口要求取消旧任务，在真正保存时执行并说明，不因只浏览选项就停止任务。
- 试听使用已保存设置，存在草稿时显示先保存说明；取消试听就近提供。
- 音色目录仍来自 capabilities；男女声筛选、收藏与最近使用只保存非敏感偏好。原型仅提供示意，不以少量示例目录替代正式能力目录。
- 三项许可维持用户要求的默认值及历史撤销值；撤销即时处理，不等保存、不被音色校验阻塞。勾选不会触发自动录音/上传。
- 服务技术信息默认收起；“启动/重试”沿用 ensure 语义，不包装成强制重启。

## 5. 状态与反馈

- 顶部状态使用“语音待开始 / 准备中 / 就绪 / 录音中 / 识别中 / 回答中 / 合成中 / 播放中 / 离线”，服务进程存在与会话已连接不混为同一含义。
- 常规成功在操作区显示；短提示可使用全局 toast。错误和需要用户处理的提示保持可见，并提供重试/连接/查看详情，不因切页面丢失。
- 全局停止固定可见。正式版覆盖录音、电脑播放、在途请求、设备操作、手动动画和气泡计时器；旧 generation 不能复活。
- UI 要标记 busy/disabled 原因；后台校验同样有效，不以禁用按钮代替接口安全。

## 6. 范围与实施拆分

本次交付只含设计原型、规格和验收规划。正式改造建议作为 v0.10.0，继续沿用 PRD 18 的独立语音复用边界。原型不是新服务，不接 API，不录音、不云请求、不扫描/连接设备、不修改真实设置。

| 阶段 | 实施内容 | 完成条件 |
| --- | --- | --- |
| P0 | 建立现有版本回归与快照，确认脏树责任范围 | 原有业务测试结果记录，正式服务不被原型占用 |
| P1 | 视口应用壳、删除介绍、左侧常驻机器人/右侧标签页、固定输入、模块标签切换、键盘/响应式 | 正常视口无 body 滚动，机器人持续可见，操作栏始终可达 |
| P2 | 首页准备、控制权申请与冲突提示、当前区域反馈、设备禁用条件 | 语音离线仍可设备控制；冲突明确确认；错误可见 |
| P3 | 消息/草稿分离、点击录音状态机、停止/取消、独立重试朗读 | 输入不被回复覆盖，IME/忙碌/失焦边界回归 |
| P4 | 角色中文列表、目标约束、设备实验子页、设置草稿/保存、音色检索偏好 | 功能无遗漏，配置与隐私的生效时点清楚 |
| P5 | 自动回归、实际窗口缩放、人工音频/设备验证、文档收口 | 区分源码通过、原型验证与真实运行验收 |

潜在修改路径：static/index.html、style.css、app.js；必要的消息状态/模块标签逻辑可提取小模块；companion/control.py 等只在接口缺口有证据时调整；Electron main.js 只处理窗口尺寸与恢复边界。继续共用 audio-client.js、gork-avatar.js 和 catalog，不改外部语音引擎与固件。

不改设备、不烧录、不搬模型/venv/Key、不优化实时 BLE、不推远端、不更新旧安装包。正式实例重启与真实设备/云端调用按当前任务授权另行处理。
