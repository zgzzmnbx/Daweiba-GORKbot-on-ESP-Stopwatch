## 1. 产品定位与本轮目标

Gork 控制台是个人使用的统一入口：在电脑上说话、处理文字、与机器人对话；操控桌面角色；连接和控制 StopWatch。语音引擎继续作为独立服务，控制台负责交互、状态协调和生命周期，不复制外部仓库、模型、环境或密钥。

用户现在看到的是一页堆叠的功能卡片。连接、授权、音色、音量、硬件实验与日常对话混在一起；使用者需要先理解实现细节才能操作。本轮按使用目的重组，不重写硬件驱动，也不另起一套控制平台。

交付后的主导航只有四项：**对话、角色、StopWatch、设置**。日常首页专注输入和回复；调试信息只在明确打开的诊断区出现。

成功标准：

- 首次进入，能够直接看懂“这里说话/输入、这里查看回复、这里停止”；不用先滚动寻找设置。
- 音色、语速、试听和保存集中在一处，显示真正可用的能力，不提供伪选项。
- 不启动语音引擎，也能进入角色页进行本地预览、取得控制权并使用已有设备控制功能。
- 一个后端、一份操作状态、一个 BLE 客户端；页面切换不创建新会话或新连接。
- 旧的停止、取消、上传许可、陌生端拒绝、迟到结果丢弃、设备断连边界不能退化。

## 3. 范围与明确不做

### 3.1 必须完成

四页导航、对话工作区、统一语音设置、角色预览及手动控制、StopWatch 日常控制与实验区、全局状态与停止、最小控制权解耦、桌面状态接入、客户端音频模块提取、独立语音 HTTP 调用示例、回归和使用说明。语音识别/合成可被其他程序使用，不能绑定 Gork 界面或 Watch 存在。

### 3.2 本轮不做

- 不改固件、分区、协议安全设置或设备驱动，不烧录、不清蓝牙绑定。
- 不优化 BLE 实时流，不引入 Wi-Fi、蓝牙耳机协议、唤醒词、持续监听。
- 不新增语音供应商、模型下载、账户系统、云端部署、电脑工具调用或任意命令执行。
- 不搬迁独立语音服务仓库、模型、venv、Key，不合并 Git 历史。
- 不做音色克隆、表情编辑器、角色市场、历史对话数据库、复杂主题系统。
- 不为桌面实现 happy-work 纸笔层；不承诺网页和 Watch 逐帧一致。
- 不增加 Watch 远程亮度/电量等现有协议未提供的能力，不伪造电量数据。
- 不更新旧 v0.8.0 发行包；本轮交付源码及现有根目录启动器可启动版本。跨电脑便携包另立任务。

## 5. 页面规格

### 5.1 对话：默认首页

1. 新打开应用默认进入对话；支持 `#dialogue`、`#character`、`#watch`、`#settings` 深链接与浏览器前进/后退。未知 hash 回对话，不刷新整个应用。
2. 会话区域区分用户输入、识别结果、AI 回答和系统状态。录音完成先显示可编辑转写，不未经确认自动上传给回答服务；由“发送并朗读”推进后续步骤。
3. 两种模式：`朗读/跟读`（不调用回答服务）；`AI 对话`（确实调用回答服务后朗读回答）。未配置 AI 时禁用后一项并提供“去设置查看”，不能伪造回复或悄悄退回朗读后显示成功回答。
4. 文字输入保留现有服务长度限制；提交前提示。中文输入法组合期间 Enter 不触发；Enter 发送，Shift+Enter 换行。
5. 录音由明确按住操作开始，松开结束。键盘等效操作、指针移出、窗口失焦、`pointercancel` 都有可靠结束路径；不得悄悄持续收音。沿用现有最长录音限制。
6. 点击发送前要有工作台控制权；需要 ASR/TTS 时再建立或复用语音会话。服务加载中显示加载状态，防止重复点击创建多个任务。
7. 本轮日常对话默认电脑麦克风/扬声器。Watch 音频放实验页，不让用户误以为输出目标切换后可以实时对话。
8. 会话消息仅在内存中，刷新/退出清除，不把录音、转写、回答写入 localStorage、Git 或普通调试日志；不新增永久聊天记录。
9. “清空会话”清除可见内容并调用清空回答上下文；独立显示清空失败，不只清掉前端。
10. 顶部显示录音、识别、等待回答、合成、播放等真实阶段，停止按钮始终可见；零输入时主提交禁用。

### 5.2 角色：一套角色，多端控制

布局：大预览 + 当前表情/目标/播放方式 + 表情选择区 + 气泡输入；桌面窗口设置放该页下方，不和音色混排。

- 使用正式 Grok bot 数据、同一渲染器；不要用 CSS 双椭圆替代时间轴，也不要重新生成美术资产。
- 23 个来源动画以生命周期/反应两组呈现；列表只显示名称及静态缩略，只有当前预览运行动画，避免几十个 Canvas 同时 RAF。
- 点选只预览，明确点击“播放到目标”才对桌面或设备产生动作。目标：桌面小人、StopWatch、两端；各目标在线状态和能力单独显示。
- `happy-work` 以第 24 项显示并标“仅 StopWatch”；选桌面/两端时禁用提交并说明原因，不偷偷用 happy 代替。
- 默认单次播放；idle 持续。非 idle 播完自动回 idle；提供显式循环及“返回自动联动”。本轮不必增加 pingpong UI，旧串口功能不删除。
- 单次时长由正式序列计算，不统一硬编码为几秒。再次手动播放同一名称应重新起播；业务轮询重复上报同一状态则不能每 500 ms 重启动画。
- 业务状态仍可联动 listening/thinking/happy/confused；开始语音任务时结束手动循环，任务结束回 idle。忙于语音或设备音频时禁用手动发送，服务端也应拒绝冲突，不把命令排队到稍后意外执行。
- 同步两端不意味着帧同步。分别返回桌面接收/设备回执/失败状态；任一目标失败显示“部分完成”，不自动无限重试，不重放旧文字。

气泡规则：

- 手动气泡为纯文本，直接显示，不调用 ASR/TTS/AI。使用安全文本绘制，不解析 HTML。
- 桌面最多 300 字符，支持换行和中文。Watch 保留现有 BMP、24 字符且 ≤72 UTF-8 字节限制；使用 Watch/两端时在编辑区显示实际计数、预览和不支持字符原因。
- 手动输入超限必须拦截或让用户明确确认裁剪，不静默截断。自动语音状态的小气泡沿用既有缩短规则并注明是摘要。
- 手动气泡显示 8 秒自动清除，也可手动清除；新气泡替换旧气泡，不建立播放队列。Watch 到期由电脑发已有清除命令，失败不得称已清屏。
- 桌面气泡不得被透明窗口边界裁掉；出现/消失不能改变角色中心、导致窗口位置跳动。旧目标/旧 generation 的计时器不得清掉新气泡。
- 断开、接管、停止时取消手动状态和计时器；重连不自动重发文字。

桌面选项：显示/隐藏小人、恢复默认位置、始终置顶开关。通过已有受限 preload/IPC 扩展，不能开放任意命令、路径或通用 shell。网页环境没有桌面桥接时明确禁用窗口选项，仍能预览；不能假装已创建桌面窗口。

### 5.3 StopWatch：日常功能优先

页面顺序：连接 → 内置声音/音量 → 实验功能 → 诊断。

- 连接区展示未连接/扫描中/连接中/已连接/断开原因；显式扫描后选择设备，不凭历史 COM 或蓝牙地址假定当前目标。
- BLE 表情、声音和音频复用当前单一 BleakClient，不能每个面板各建一条连接。旧独立 BLE 工具继续保留，说明不能并行占用。
- 六个声音卡片提供“电脑试听”和“设备播放”，标签必须区分播放端。电脑试听不需要 Watch，但也不得与主 TTS 无规则叠播。
- 音量滑块显示提交中/设备确认值；合并快速拖动请求，松开最终提交，防止每像素发一次 BLE 写入。失败时保留错误或回滚显示，不显示假成功。
- 没有读取接口的信息显示“暂不可读取”，不能把本地缓存当设备当前值。设备电量/亮度不列为本轮远程能力。
- 实验功能沿用既有三条路径：`device-pc` 设备录音→电脑播放（直接回放，不自动识别）；`pc-device` 电脑合成语音→设备延迟播放；`device-process-device` 设备录音→电脑识别/可选回答/合成→设备延迟回复。页面必须准确标明是否调用识别/回答，不能把直接回放包装成处理。
- 实验区显著标“非实时，传输可能需要几十秒”；录音、上行、处理、下行、播放状态分开。字节与速率来自实际任务，不伪造剩余时间。
- 输入、上传、回答和合成的许可分别遵循设置；设备录音不因进入实验页自动开启。
- 离开页面可保留显式启动的传输，顶部必须显示当前设备任务和取消入口。折叠实验区不能隐藏运行中任务的停止入口。
- 错误码及连接详情收进诊断，不把它们作为日常主标题。停止未确认时提醒设备 B 键可停止，不能称已经停止发声。

### 5.4 设置：频繁设置在前，诊断在后

**语音**：语音识别路由、文字朗读路由、对应音色、语速、固定文字试听、停止试听、应用并保存在一个组内。

- 音色列表来自 capabilities；不能硬编码只一项，也不把不可用音色冒充可用。旧服务仅有默认音色时给出升级提示。
- 当前云端能力仅自然 1.0×，本地可选 0.85/1.0/1.15×；以返回能力为准，并保留切回本地时的上次速度。
- 试听固定短句，不调用 AI 回答，不覆盖对话输入、不改变回答历史；需上传文字时仍受对应许可约束。
- 设置有未保存标记；试听使用已应用设置，未保存时要求先应用，避免“选了 A 却试听 B”且无提示。
- 设置保存失败不显示已保存；刷新恢复路由/音色/语速和独立许可，不恢复录音或播放动作。

**AI 回答**：展示已配置/未配置/不可用、非敏感模型名；解释与 ASR/TTS 的区别。未配置时提供受控的文字配置说明，沿用配置文件和环境变量，不在网页里新增 Key 输入/存储，不让后端返回完整配置或秘密值。

**隐私与上下文**：保留三项独立默认许可及历史撤销值；勾选只是许可，不自动上传。取消勾选立即停止/撤销相关任务，不等待“应用并保存”；不能因为音色校验失败让撤销失效。说明浏览器麦克风授权和这些许可是不同层次。

**服务与诊断**：在线、模型加载中、就绪、启动失败、复用外部服务/本应用托管分别显示。按钮用“启动/重试”，不得把已有 ensure 接口包装成强制重启。复用的外部服务不随控制台退出被杀；默认收起 URL、版本、实例与错误详情，日志脱敏。

提供独立“释放语音会话”入口，先取消本应用语音任务，再让其他程序取得语音服务；不释放工作台的角色/设备控制权。当前语音服务是单活会话，并非多程序任意并发服务；共享托管生命周期限制见补充 18。

## 6. 全局状态、控制权和冲突规则

### 6.1 最小控制权解耦

当前 `Controller.authorize()` 同时要求 owner 与 voice.session，导致语音不可用时设备操作也不可用。本轮只拆开这两个条件，不新增账号系统或权限框架：

1. 保留当前客户端 UUID 与单 owner 思路；增加工作台控制权取得/心跳/释放接口，设备与角色操作只依赖工作台控制权。
2. 首次需要写操作时明确取得控制权；只读浏览和本地预览不争抢。已有 owner 时显示“另一窗口正在控制”，提供明确接管按钮，不自动接管。
3. 语音会话在需要 ASR/TTS 时再创建；语音服务离线不释放工作台所有权，也不导致 Watch 控制被禁用。
4. 工作台租期建议 30 秒，沿用 1 秒心跳；只由持有者续租，健康查询不续租。后台浏览器可能节流，过期必须安全停用而非偷偷接管；回到前台显示重新取得控制权入口。
5. 接管、租期过期或释放时先失效旧 generation，停止旧任务/计时器并清理会话，再允许新写入；旧请求不能借新 owner 身份落地。
6. 旧 `/api/session` 行为保留兼容适配，复用同一 Controller；禁止两套 owner 状态彼此不同步。新增接口继续受同源/本机边界和严格字段校验约束。

### 6.2 停止与导航

| 事件 | 必须执行 | 不能发生 |
| --- | --- | --- |
| 全局停止 / 托盘停止 | 本地立即停录音、所有电脑音频；失效代际；取消回答/TTS/实验音频；停止设备声音与手动动画；清理气泡计时器 | 等网络返回后才静音；旧结果重新播放 |
| 切换页面 | 不重建心跳/BLE；正在录音则结束并提示，保留已有可编辑结果 | 隐藏页面继续无提示收音 |
| 切页时正在播放/传输 | 可以继续，顶部显示进度及停止入口 | 隐藏任务、创建第二个播放实例 |
| 撤销上传许可 | 立即取消相关路径，更新服务路由/许可 | 因设置未保存继续上传 |
| 设备断连 | 标记不确定/失败，终止相关操作，不重放气泡 | 使用旧回执宣称成功 |
| 退出/释放/接管 | 清理 owner、待处理任务及迟到结果；仅关闭自有服务 | 关闭用户自行启动的独立服务 |

电脑本地静音不能依赖 BLE 锁。设备音频持锁传输期间，取消应有独立可达路径，不能排在整段传输之后。设备停止超时返回“停止未确认”，与电脑已停止分别呈现。

桌面隐藏不应意外唤醒；保持当前关闭/隐藏安全策略并在使用说明中明确。无障碍导航移动焦点不会取得控制权、录音或播放。

## 7. 技术实现约束与接口建议

### 7.1 文件与复用边界

- 前端仍是现有静态 HTML/CSS/ES modules，不为四页导航引入 React、构建器或新组件库。
- 麦克风采集、完整 WAV 播放和资源释放从页面脚本提取为独立音频模块；无 DOM/角色/BLE/云凭据依赖。HTTP 客户端保持独立，具体接口、调用示例和测试见补充 18，不新增另一套语音引擎。
- `static/app.js` 可按页面拆成少量模块；状态、owner、Epoch、AudioContext、心跳、API 客户端只有一份。提取是为消除重复，禁止建无实际需要的事件总线框架。
- 角色渲染继续由 `tools/export_desktop_avatar.py` 管理同源副本；修改源渲染器后运行导出并 `--check`，不要手改两个副本。
- 后端复用 `control.py`、`robot.py`、`voice.py`、`answer.py`、`service_manager.py`，BLE 表情和气泡复用 `tools/stopwatch_ble.py`；不新增第二个 BLE/语音客户端。
- Electron 通过现有 preload 白名单与主进程交互，保留 sandbox、无 Node 的渲染进程及单实例锁。

### 7.2 新接口契约（建议命名，语义为必需）

| 接口 | 核心语义 |
| --- | --- |
| `POST/GET/DELETE /api/workspace` | 取得/读取并续租自身/释放控制权；接管必须显式 replace；无语音服务仍可用 |
| `GET /api/character/catalog` | 23 来源动画、happy-work 及各目标支持情况、时长；数据来自正式目录 |
| `POST /api/character/expression` | expression、target、mode=once/loop；严格枚举；校验控制权、忙状态、目标能力 |
| `POST/DELETE /api/character/bubble` | 纯文本发送/清除；target；服务器再次检查字数、编码、TTL、owner |
| `GET /api/desktop/state` 扩展 | 保留旧字段；增加实际角色状态、animation_id、playback_id、mode、气泡和 generation |

接口名可在 M0 结合当前路由微调一次并写入报告，不能实施中多套重复。请求/响应使用稳定机器码：`busy`、`not_owner`、`target_offline`、`unsupported`、`invalid_text`，前端映射清晰中文。

角色写操作建议返回 `operation_id`、`generation` 和逐目标结果。它们只是电脑端关联标识，**不代表旧 BLE 表情协议已有逐命令事务号**。BLE 仍需单写入者、匹配回执、超时断开和不重放旧文字。

后端接收桌面播放状态不等于已看见桌面。桌面主进程应以轻量存活/接收回报标识存在（建议 2 秒上报、6 秒过期），不得据“HTTP 200”声称窗口已呈现。状态缺失时显示桌面未运行；仅网页预览仍可用。新回报只允许固定状态字段，不能成为 OS 通用控制接口。

角色状态区分自动业务状态与手动覆盖。`playback_id` 仅在新播放动作变化，轮询不递增；一次播放结束按正式时长回 idle。跨目标处理结果不必原子一致，但必须显式报告部分失败。

### 7.3 旧设置迁移

保留 `gork.audio-consent`、`gork.text-consent`、`gork.answer-consent`、`gork.asr`、`gork.tts`、`gork.speech` 的读取兼容；需要新 schema 时一次迁移并测试。明确保存的 false 永远优先于默认 true。禁止保存录音、气泡文字、聊天历史或密钥。

## 8. 视觉与可用性规范

- 沿用当前米白底、橄榄绿主色、暖灰文字、细边框与圆角，不换品牌、不引入大型渐变/霓虹背景。
- 主操作一页只突出一个；危险/停止操作用稳定高对比样式，禁用状态有原因而非仅灰色。
- 推荐整体内容最大宽度 1280 px、侧栏 168–184 px（或等效顶部四页导航）；页面间距 24 px、组内 12–16 px。不要固定巨大卡片高度制造空白。
- 1180×820 初始对话页应看得到输入框、主操作和停止；长会话在消息区滚动。其他页面允许正常纵向滚动。
- 900 px 以下合理改单列；390 px 宽无横向溢出，导航可紧凑排列。桌面头像按现有约 240×280 窗口检查气泡和按钮不裁切。
- 所有输入有 label；焦点可见；状态不能只靠颜色；支持 Tab、Enter/Space 和必要的 aria 状态播报。高频进度不要每帧读屏。
- 动画预览尊重减少动态效果偏好；不影响用户明确触发的表情查看。隐藏预览应暂停 RAF 或释放实例。
- 空、加载、离线、未配置、权限不足、部分完成都有可恢复动作；不只吐异常堆栈。

## 9. 验收与完成口径

详细用例、阶段门禁和运行命令见任务书 17。本轮分三类证据：

1. 自动测试：业务状态、取消、权限、路由、目录、协议模拟与 Electron IPC。
2. 本机 UI：四页真实浏览器截图及交互；实际 Electron 小人、托盘和窗口检查，条件不具备明确说明。
3. 人工/外部：真机表情/声音/气泡、真实麦克风听验和云端付费路径。未跑记录 NOT_RUN，不能用前两类替代。

Goal 目标限定为本轮软件实现与可执行验证交付。强制自动测试或关键 UI 流程失败不能标完成；依赖用户设备/凭据/操作授权的验收单列待确认，不为了追求“全绿”扩大权限。

不需要为本次界面优化烧录 StopWatch。最终报告必须说明电脑端版本、设备版本、独立服务版本各自是否变化；v0.9.0 不得写成设备也升级到了 v0.9.0。

## 10. 风险、回退与后续

最大风险是重组时重复创建音频对象/心跳、打断 owner 逻辑，或把业务动画和手动动画混成无限循环。其次是“停止全部”只停止当前页面、桌面无在线证据仍显示成功，以及 UI 接受 Watch 不支持的字符。

回退以本轮明确修改的文件/提交为单位；保留用户已有脏改动，不执行整仓 reset/clean。先交付无新框架的界面和控制链，再考虑发行包。实时 BLE、桌面 happy-work 纸笔层和设备远程亮度/电量作为后续独立需求，不自动纳入本轮。
