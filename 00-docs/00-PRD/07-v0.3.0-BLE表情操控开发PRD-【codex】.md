## 1. 背景、事实与边界

大尾巴已用 USB Type-C/COM 串口控制 StopWatch 表情，并希望改用本电脑蓝牙无线控制。当前 v0.2.5 固件提供 23 条表情序列，Windows USB 控制台可发送 happy、loop happy、idle；2026-09-17 真机串口曾返回 Command accepted: HAPPY。

| 项目 | 已确认事实 | 尚未确认 |
| --- | --- | --- |
| StopWatch 芯片 | 本项目识别为 ESP32-S3；官方说明 ESP32-S3 支持 BLE、不支持经典蓝牙 | 现有 v0.2.5 固件没有 BLE GATT 服务，尚未广播或配对 |
| Windows 电脑 | Windows 11 build 26200；Intel Wireless Bluetooth、Microsoft BLE 枚举器状态 OK；蓝牙服务运行 | 本机与新增 StopWatch BLE 服务的扫描、配对、重连尚未实测 |
| PC 运行时 | Python 3.14.3；用户级已装 Bleak 3.0.2 | 独立项目环境、目标设备服务发现和 GATT 写入尚未建立 |
| 固件栈 | PlatformIO espressif32 6.12.0 / Arduino core 2.0.17，包内有 BLE GATT Server、BLESecurity 和加密写权限 API | 同现有 M5Unified、显示渲染、PSRAM 的构建与运行时共存需试验 |
| 工作树 | 正式源码仓库有既有未提交改动 | 不得 reset、clean、覆盖或顺手重构 |

技术路线为 BLE GATT，而非经典蓝牙 SPP/RFCOMM 或“蓝牙虚拟 COM 口”。COM3/COM4 是本机其他蓝牙串口，不得拿来写 StopWatch；现有 USB COM 口继续用作恢复和调试。Windows BLE GATT 客户端使用本机蓝牙适配器，无额外硬件。

## 2. 产品目标与非目标

### 2.1 目标

1. 不接 USB 数据线时，Windows 电脑能扫描、配对并连接 StopWatch。
2. 在可双击命令行窗口输入表情名，设备以与 USB 串口相同的规则播放表情；非 idle 默认播放一遍后回 idle。
3. 支持 once、loop、pingpong 三种显式播放模式，且 Windows 端能看到设备处理结果，不把“写请求已发出”当作“表情已播放”。
4. 断线、电脑蓝牙暂时关闭、StopWatch 重启后可恢复连接；蓝牙故障不破坏设备本地交互或 USB 通道。
5. 默认不接受附近任意设备写入表情；由设备本地开启配对窗口，并只允许已绑定的这台电脑加密写入。

### 2.2 非目标

- 不做经典蓝牙 SPP、A2DP、音频、BLE Mesh、手机 App、网页蓝牙、Wi-Fi、云端或远程互联网操控。
- 不通过 BLE 传输表情图片、动画帧或固件；BLE 只发送短命令。
- 不重做 Grok bot 渲染器、23 条时间轴、亮度、电量、触摸、按键和 IMU 逻辑。
- 不在本期改分区表、bootloader、安全启动、Flash 加密或 eFuse。
- 不把“电脑内置蓝牙存在”视为“已完成 BLE 配对或无线操控”。

## 3. 用户路径

1. 大尾巴在 StopWatch 的 Settings → Bluetooth 页面把 BLE Control 打开，点击 Pair 开启 120 秒配对窗口；首次升级默认关闭 BLE，避免无意广播和额外耗电。
2. 在本电脑双击新的 BLE 控制台。程序检测本机适配器，扫描下面固定服务 UUID；若找到多个同类设备，列出供人工选择，不静默连接任意一个。
3. 控制台提示或触发 Windows 配对。成功后显示连接状态、设备名和协议 v1（由固定服务 UUID 判定）；不把 USB MAC/COM5 当成蓝牙地址。
4. 在提示符输入 happy、thinking、celebrate 等；输入 loop happy 持续播放，idle 返回待机；:list 查看 23 个标准名，:q 断开并退出。
5. 断线时控制台显示断开与重连进度；若无法重连给出蓝牙开关、设备页面、绑定状态的具体检查提示。StopWatch 仍可独立使用。
6. 大尾巴可在 StopWatch 的 Bluetooth 页面关闭 BLE、重新打开配对窗口或明确确认后清除本设备的 BLE 绑定；不清除亮度、调试模式或原始 Flash 备份。

## 4. 总体架构与代码边界

Windows 命令行/Bleak（GATT Client） → 本机 Intel 蓝牙适配器 → StopWatch BLE 广播和 GATT Server → 有界命令队列 → 主循环统一命令处理 → 既有 AvatarEngine。

- 固件依旧在 03-Src/stopwatch-grok-avatar/ 内开发。BLE 传输、协议校验和队列建议独立为 src/ble_control.*；主循环只增加生命周期、队列消费和状态回执入口。
- 抽出 USB 与 BLE 共用的表情命令分发函数，继续调用现有 AvatarEngine::showFromCommand；不得复制出第二套名称映射、播放规则或动画状态机。
- BLE 回调不得直接调用 M5.Display、avatar.showFromCommand、Preferences 写入或阻塞式 I/O；所有设备状态修改在主循环执行。队列容量固定 8 条，命令最长 20 字节，超限明确拒绝。
- Windows 端新增 tools/ble-expression-console.py、tools/start-ble-expression-console.cmd、tools/requirements-ble.txt 和必要的协议/客户端测试；现有 USB 脚本原样保留。
- 正式源码不得写死本机 COM5、Windows 蓝牙地址、个人绝对路径或用户凭据。

## 5. BLE GATT 协议 v1（实施前锁定）

| 对象 | UUID / 值 | 权限或用途 |
| --- | --- | --- |
| 广播设备名 | GorkBot-SW | 人可识别；身份仍以服务 UUID 和绑定关系判定 |
| 自定义服务 | 48f1a001-8a75-4db6-9c18-590f7e9b0a01 | 必须出现在主广播包中，以供 Windows 过滤；设备名可放扫描响应 |
| 命令特征 | 48f1a002-8a75-4db6-9c18-590f7e9b0a01 | WRITE with response；加密写权限；不提供无响应写 |
| 状态特征 | 48f1a003-8a75-4db6-9c18-590f7e9b0a01 | READ + NOTIFY；仅绑定连接可读/订阅 |

命令负载为不带结尾换行的 ASCII 小写文本，最大 20 字节：标准表达式名，或 once/loop/pingpong 加一个空格和标准表达式名。最长的既定命令也不超过 20 字节，避免依赖大 MTU；客户端不得发送 JSON、任意脚本或长字符串。标准名称为：

~~~text
idle listening thinking happy excited curious confused angry surprised sad
sleepy dizzy sleeping waking searching working bored suspicious proud shy
laughing scared celebrate
~~~

直接发送 happy 默认播放一次并返回 idle；loop happy、pingpong happy 持续播放；once happy 显式只播放一次；idle 立即回待机。Windows UI 只列标准名，固件中已存在的串口别名可继续兼容，但 BLE 协议不依赖别名。

状态特征用短 ASCII 回执，例如 OK:HAPPY、ERR:BAD_CMD、ERR:BUSY、ERR:FULL，最大 20 字节。客户端先订阅通知，再以 response=True 写命令，一次只保留一个在途命令，并在收到对应的下一条处理回执后才提示“已应用”。GATT 写响应仅表示传输层成功，不代表已切换表情；通知丢失时可读状态特征并标注“结果待确认”，不得编造成功。命令均为绝对表情状态，超时后可安全重发一次；再次超时则提示断线或重连。

当 Settings/Hardware/Bluetooth 菜单打开时，BLE 和 USB 均不触发表情；BLE 回 ERR:BUSY，不缓存到退出菜单之后突然播放。未知或过长命令不得改动当前表情、不得振动。同一时刻来自本地、USB、BLE 的操作，以主循环实际处理顺序为准，日志记录来源；不制造长期“蓝牙占有控制权”。

## 6. 配对、安全和电源

- 首次升级时 BLE Control 默认 OFF；用户在设备本地打开后才广播。已有绑定且开关保持 ON 时，重启后允许该电脑自动重连；未绑定时必须由设备本地再次打开 120 秒 Pair 窗口。
- 命令特征至少要求 BLE 链路加密和 bonding，设备最多保存一个控制端绑定。仅“Windows 已发现/连接”不能赋予写权限；配对窗口外的陌生设备写入必须失败。
- 当前硬件没有独立键盘输入。若采用 Just Works 安全连接，其链路加密不等于抗中间人验证；PRD 不声称 MITM 防护。Luna 须在 G1 核对当前 Arduino BLE 栈的安全 API、权限设置与构建结果，在获授权烧录后的 G4 实测 Windows 配对、加密权限和绑定限制；任一阶段发现无法可靠限制未授权写入即停下报告，不以开放写权限交付。
- 如需清除绑定，必须在 StopWatch 本地 Bluetooth 页面显式二次确认；只清除 BLE 配对材料，不清理其他 NVS 设置。Windows 端仅解除与该 StopWatch 的配对，不操作鼠标、键盘、耳机等其他设备。
- Settings 首页原有电量、亮度、调试开关和 Hardware Check 必须保留。可增设 Bluetooth 子页入口，但布局要在圆屏安全区内，不能遮挡已有控件；BLE 启停、配对窗口和绑定状态应可见。
- 停止广播或断线不改变当前表情；BLE OFF 后释放相关资源，手机/其他电脑不应还能写入。记录 BLE OFF、广播、已连接三种状态下的电流或至少可比较的电量实验条件；无测量设备时写 NOT MEASURED，不宣称低功耗。

## 7. Windows 客户端要求

- 本项目仅要求这台 Windows 11 电脑；本机快照为 Intel Wireless Bluetooth 状态 OK、Microsoft BLE 枚举器状态 OK、Python 3.14.3、Bleak 3.0.2 已安装。实施仍须建立项目隔离环境并固定 Bleak 版本，不依赖用户级全局包长期存在。
- 采用 Bleak 的 Windows/WinRT 后端，以扫描到的 BLEDevice 实例连接；按固定服务 UUID 过滤，不固定设备 MAC/地址。发现多个目标时人工选择。
- 在普通 Python 控制台运行 asyncio/WinRT 客户端，避免无事件循环的 STA 线程造成 Bleak 挂起；服务 UUID 要进主广播包，不能只依赖 Windows 合并扫描响应。
- 客户端检测蓝牙关闭、未找到设备、配对取消、服务 UUID 不匹配、加密权限错误、设备已断开、状态通知超时，分别显示可操作提示。
- 优先用 BleakClient(pair=True) 验证 Windows 配对流程；写特征显式 response=True，订阅通知并处理 disconnected_callback。不要把普通串口脚本包装成“蓝牙版”。
- 客户端是可双击的命令行窗口；不需要安装包或托盘常驻。退出时取消通知、断开连接并释放资源；不在后台持续扫描。
- 交付安装/启动说明、:help/:list/:q、断线重试说明；不得自动发送未知或危险指令到其他 BLE 设备。

## 10. 风险、阻塞与回退

1. **Arduino BLE 栈与现有固件共存**：运行时堆、帧率或 USB CDC 可能受影响。优先使用当前锁定 core 自带 BLE；若必须改用兼容 NimBLE，先记录依赖版本和原因、验证旧功能，不得擅自升级 PlatformIO/Arduino 全栈。
2. **Windows 配对与缓存**：Windows 可能缓存旧 GATT 布局；先固定 UUID/特征，再真机配对。若更新布局造成异常，仅解除本 StopWatch 的配对并重新配对，不重置整机蓝牙。
3. **安全门禁**：G1 只能确认安全 API 和构建具备实现路径，不能预先证明运行时配对成功。若 G1 无法表达加密绑定，或 G4 实测无法限制陌生端控制，该门禁判失败，不以“个人使用”为理由开放命令特征。
4. **圆屏 Settings 空间**：新增 Bluetooth 入口须先做圆屏布局截图/实机观察；原亮度、电量、调试开关和 Hardware Check 不得挤压失效。
5. **设备变砖/连接失败**：保留完整 Flash 原始备份与 v0.2.5 应用镜像；普通回退仅写旧应用区，不自动整片恢复。任何整片写入需单独确认。
6. **项目脏工作树**：既有修改归用户所有；仅操作 v0.3.0 范围文件，列出新增/修改清单，不 reset、clean 或覆盖。
