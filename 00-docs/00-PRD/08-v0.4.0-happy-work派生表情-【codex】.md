# v0.4.0 `happy-work` 派生表情与验收

> 日期：2026-09-17
> v0.4.0 独立镜像未烧录；该表情已包含于写入并读回校验通过的 v0.5.0，真机视觉与性能待验收。
> 本文件本身不授权后续设备写入。

## 1. 目标和边界

大尾巴希望从现有 `happy` 派生 `happy-work`：保留完全相同的开心眼睛，在黑色圆体下半部出现一只握笔的小手，在纸上持续写字。它是本地新增表情，不修改 Bible Strong Avatar Lab 导出的 27 个 preset / 23 条 sequence，也不替换现有 `happy` 或 `working`。产品仍使用黑体、白眼、白/浅灰线条，不加入图片帧、音频或联网功能。

## 2. 行为规格

| 项目 | 规则 |
| --- | --- |
| 名称 | 设备调试标签与回执为 `HAPPY-WORK`；串口/BLE 命令为 `happy-work` |
| 眼睛 | 直接引用来源 `happy` 的 4 帧关键帧、眨眼和运动参数，不复制或重新生成眼睛数据 |
| 书写层 | 466×466 基准坐标中，仅使用黑色圆体内的下半部安全区域：纸张、横线、逐步延伸的笔迹、移动笔尖与握笔小手 |
| 动画 | 笔迹 1.9 秒写满一行，2.6 秒重新开始；与 `happy` 原眼睛时间轴同步运行，不阻塞输入或 BLE 回调 |
| 播放 | 直接调用默认播放一遍后回 `idle`；`once` 同义；`loop` / `pingpong` 显式持续；切走后下一帧擦除纸笔残影 |
| 命令 | USB 与 BLE 均支持 `happy-work`、`once happy-work`、`loop happy-work`、`pingpong happy-work`；最长为 19 ASCII 字节，未扩大 BLE 20 字节上限 |
| 数量口径 | 23 条上游来源序列不变；加上本地派生后共 24 个可调用表情 |

## 3. 实施位置

- `03-Src/stopwatch-grok-avatar/src/avatar_engine.h/.cpp`：新增枚举、派生 spec、书写层和局部擦除；保持原 23 条生成表及 `happy` 原语义不变。
- `03-Src/stopwatch-grok-avatar/src/ble_control.cpp`：仅放行命令中的连字符，实际合法表情仍由统一 `showFromCommand` 决定。
- `tools/ble-expression-console.py`、`tools/stopwatch-expression-console.ps1`：列出并发送新表情；`tools/test_ble_expression_console.py` 检查名称及 20 字节边界。
- 图层绘制仍在主循环，不在 BLE 回调中；使用已有 60 FPS 调度和黑体局部刷新。

## 4. 验收门禁

1. **源码/静态**：新表情引用 `happy` 原眼睛数据；来源生成脚本仍校验 27 preset / 23 sequence；原 `happy`、`working`、菜单与本地输入行为不改。
2. **命令**：USB 与 BLE 客户端均接受四种 `happy-work` 命令，拒绝未知带连字符名称；设备 `OK:HAPPY-WORK` 只代表命令已处理，不代替实物目视。此前验收发现的 BLE 旧回执误判与自动重连问题仍须另行修复，不能把它们标成 v0.4.0 已解决。
3. **构建**：17 项现有 Python 测试和正式 PlatformIO 构建通过，固件大小不超既定应用分区；归档版本化 `.bin`。本机结果：RAM 62,672/327,680（19.1%），Flash 1,541,201/6,553,600（23.5%）。
4. **烧录**：需大尾巴当次明确确认后重新枚举 USB 端口、核对芯片/MAC 和恢复点，只写 `0x10000` 应用区并由烧录工具校验、设备读回；不整片擦除、不改 eFuse/分区/安全配置。当前 **NOT RUN**。
5. **实物视觉与性能**：拍摄至少一段连续视频，确认眼睛与 `happy` 一致、握笔动作和笔迹可读、切换及返回 `idle` 后无残影；读取 `happy-work` 的 FPS 与渲染耗时，与 v0.3.0 待机基线比较；BLE/USB/按键/触摸仍可控制。当前 **NOT RUN**。

## 5. 已知边界

- 当前动画是小尺寸程序化图形，不是网页 3D 手臂或逐帧图片；“握笔”的最终辨识度必须以 466×466 AMOLED 实物为准。
- v0.3.0 BLE 的陌生端拒绝、10 次重连、延迟、FPS 与 30 分钟稳定性仍未完整验收；本版不继承其未完成项为 PASS。
- 正式源码仓库原有未提交 Grok 渲染改动，本次保留，不做 `reset`/`clean` 或包含它们的整批 Git 提交。
