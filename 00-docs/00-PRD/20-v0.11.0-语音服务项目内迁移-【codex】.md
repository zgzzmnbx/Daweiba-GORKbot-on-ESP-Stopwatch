# v0.11.0 语音服务项目内迁移

2026-09-23，文档 v1.0.0。用户明确要求“把语音服务也给我迁移过来，不要去跨项目文件夹找文件了”。本次授权覆盖此前禁止复制语音源码、环境和模型的历史阶段边界；不授权删除来源目录或改变固件。

## 范围与实施

- 语音源码、配置模板、测试及托管入口导入 `03-Src/voice-service/`，保留 HTTP v1 接口和纯语音模块边界；不合并其他仓库 Git 历史。
- 模型复制至 `Codex-Temp/voice-runtime/models/`，在 `Codex-Temp/voice-runtime/.venv/` 建立本机独立环境。实际启动不再引用旧项目。
- Key 继续使用已有 Windows 专用环境变量，不读取到文档、不复制进文件、不进入 Git。云端许可和取消逻辑保持原样。
- 控制台默认启动入口按项目目录解析；现有本机配置迁移并备份。保留显式外部服务配置用于通用客户端，但本机运行默认指向本项目。
- Astra 负责资产/环境迁移、宿主集成、验证和记录；Sol 仅负责 `03-Src/voice-service/**` 源码导入与路径适配/单元测试，互不修改责任文件。

## 验收

1. 来源保留，复制清单可核对，模型与环境无指向旧目录的链接或活动配置。
2. 新环境导入依赖通过、服务全部自动测试及控制台回归通过。
3. 使用迁入代码和模型在隔离端口启动，真实本地 TTS WAV 与 ASR 请求通过，停止后模型子进程退出。
4. 控制台默认启动配置、健康/能力目录与会话验证；不发云端请求，不录真实麦克风，不连接设备。
5. README/AGENTS/当前计划/CHANGELOG、模块来源和迁移验收记录同步。版本为电脑端 v0.11.0-dev；语音服务沿用 0.3.2，固件不变。

迁移前限定配置备份：`Codex-Temp/voice-migration-before/`。验证失败时恢复本机配置，保留新副本排查，不删除来源。
