# v0.5.0 BLE 文字聊天气泡 PRD

> 日期：2026-09-17
> 当前状态：源码、Windows 控制台、测试与应用镜像已完成；收到大尾巴当次指令后已仅写入设备应用区并读回校验，真机显示与无线链路待验收。
> 本文件本身不授权后续烧录；设备应用区现为 v0.5.0。

## 1. 目标

大尾巴在现有 Windows 蓝牙命令行输入一段文字，StopWatch 保持当前 Grok bot 表情，在角色头部上方显示对应的两行聊天气泡。表情控制命令、设置页、顶部调试标签和 `happy-work` 保持原有行为。文字只在绑定电脑与设备的加密 BLE GATT 链路上传输，不经 Wi-Fi、云端或额外手机。

## 2. 用户行为

- 输入 `:say 你好，今天加油！`：设备收齐并校验后显示文字，控制台收到 `OK:TEXT:<id>` 才确认显示命令已处理。
- 新的 `:say` 替换旧气泡；`:` 后的普通表情命令照常工作，气泡不改变当前表情。
- 气泡约 10 秒后自动消失；输入 `:clear` 立即清除。设备重启后不恢复气泡，不写入 NVS。
- 输入不超过 24 个可打印 BMP 字符、UTF-8 不超过 72 字节。暂不支持 emoji、换行和超过两行的长消息；控制台在发送前给出明确错误。
- 停留在设备 Settings/Bluetooth/Hardware 菜单时，文字包与表情命令同样返回 `ERR:BUSY`，不在退出菜单后突然显示。

## 3. BLE 扩展协议

沿用 v0.3.0 的同一加密 Command WRITE-with-response 特征和 Status NOTIFY 特征，不修改 UUID、分区表或配对信息。单次写入仍 ≤20 字节；所有包由原授权回调有界入队，主循环处理。二进制首字节与旧 ASCII 表情命令区分：

| 操作 | 内容 | 成功回执 |
| --- | --- | --- |
| Begin `0xF0` | `[0xF0, id, total_utf8_bytes]`；`id` 为 1–255 | `OK:BEGIN:<id>` |
| Chunk `0xF1` | `[0xF1, id, sequence, payload]`；payload 最多 17 字节 | `OK:PART:<id>:<sequence>` |
| Commit `0xF2` | `[0xF2, id]`；设备确认总字节数、顺序与 UTF-8 有效后一次更新画面 | `OK:TEXT:<id>` |
| Clear `0xF3` | `[0xF3]` | `OK:CLEAR` |

超时、乱序、超长、无效 UTF-8 或未绑定写入不得更改当前气泡；传输中断后新的 Begin 重置旧的未完成传输。错误回执使用 `ERR:TEXT_STATE`、`ERR:TEXT_SEQ`、`ERR:TEXT_UTF8` 或既有 `ERR:BUSY/AUTH/FULL`。Windows 客户端每包等待与事务 ID/序号匹配的通知，不读取旧状态来冒充成功；超时明确显示“结果未确认”，不自动重复非幂等 Chunk。

## 4. 显示设计

- 466×466 圆屏基准下，气泡位于画面上方约 `x=58–408, y=61–142`；调试小字仍在 `y=42`，不互相覆盖。
- 深灰底、白色细线边框和尾巴，文字为白色 `efontCN_16`，最多两行、每行 12 个 Unicode 字符。仍以黑体白眼为主体，不改绘制眼睛的来源时间轴。
- 气泡是独立可清除的渲染层；新气泡替换、过期、`:clear`、切换表情或菜单进出都不得留下矩形残影。保持局部刷新，真机测量气泡显示时 FPS。
