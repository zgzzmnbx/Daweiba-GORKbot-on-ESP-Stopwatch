# v0.19.0 动效编辑器接入与 Watch 映射

版本：电脑端 v0.19.0-dev；Watch 源码/编译候选 v0.10.0-dev。日期：2026-10-03。

## 1. 范围与权威来源

按用户请求读取 Windows 交接包中的提示词、接入指南、验证记录与源码。附件作为需求和实现输入；不执行拉取、自动提交、推送、发布或刷机。保留当前 Windows 工作区及原有 Codex/造价哨兵、语音、BLE、气泡、形象库和旧表情。

权威初始参数为包根目录 `gork-scenes.gork.json`，原始字节保存在 `03-Src/stopwatch-voice-companion/static/motion/initial-config.gork.json`。首次无保存文件才读取它；后续启动读取最新有效保存记录，不用源码默认值覆盖。四场景固定为 idle/loading/writing/question，四笔型 quill/nib/pencil/brush。书写只绘制笔和笔迹，无手套或纸框。

## 2. 桌面闭环

控制台新增“动效编辑器”标签页，同源 iframe 仅在进入时加载，离开销毁。入口源码为 `ui/console.html`，由 UI 构建生成 `static/index.html`；经典与 Mantine 均有 iframe 尺寸规则。依赖继续使用当前仓库的 avatar-engine/avatar-presets，不覆盖为附件的 vendor 版本。

编辑及预览只更新草稿。点击“保存并应用桌面”依次执行：严格验证 → 带 expected_revision 的本机 HTTP 保存 → 原子文件写入 → Electron 读取该保存修订 → 专用 IPC 发送给桌面播放器 → 播放器校验及应用 → 带请求编号和修订号的 ACK。只有磁盘成功才显示已保存；只有播放器 ACK 成功才显示桌面已应用。应用失败可点击“重试桌面应用”，使用保存记录而非未保存草稿，无需重启小人。

首次 idle 直接消费用户配置；一次旧表情完成后回到配置后的 idle。切换旧表情、新场景或形象时，先 dispose 旧播放器，保持一个活动 RAF。原有其他角色及彩色 Gork 待机继续使用原渲染器；本次四场景编辑器固定黑白。已有任务表达式含义不自动更改。

配置保存后，新程序进程中的桌面即时生效。正在运行的旧版需要用户先正常退出并重开一次以加载新增代码。系统减少动态效果仍有效；编辑器可明确启用“本页循环”，不修改 Windows 设置。

## 3. 配置、并发、错误和恢复

| 内容 | 路径或约定 |
| --- | --- |
| 正式配置 | `03-Src/stopwatch-voice-companion/motion.local.json`，本机忽略 |
| 记录结构 | `{revision: 正整数, config: gork-motion-studio v2}` |
| 最近有效备份 | `motion.local.json.bak`，同目录 |
| 浏览器草稿 | localStorage `gork-motion-draft-v2`，含 baseRevision；不自动覆盖正式记录 |
| 首次用户快照 | `static/motion/initial-config.gork.json`；1869 字节，逐项及字节一致 |
| 导出桌面资源 | `tools/export_desktop_avatar.py`，含 motion/、初始配置、许可及旧表情白名单 |
| 对应源码下载 | `static/motion/source.zip`，由 `tools/export_motion_source.py` 生成，不含本机状态、模型环境或凭据 |

共享字段定义为 `gork-config.js` 的 fields；后端使用对应 `field-specs.json`。拒绝未知/缺失字段、非有限数值、字符串数值、布尔数值、非法版本或笔型；配置最多 20 KiB，HTTP 实际流读取最多 24 KiB。v1 显式迁移：移除旧 handScale、补 quill 和 strokeWidth=3，其余合法字段保留；v2 不删参数。

保存使用固定受限路径、进程锁、CAS 修订检查、同目录临时文件、flush/fsync 和 os.replace。旧窗口返回 409，读取最新版本后才能再保存；磁盘失败返回错误并保留有效记录。主文件损坏时读取最近有效备份并提示，损坏原文件不会在读取时被覆盖。两个文件都损坏时禁止普通保存；必须显式导入有效 JSON，再执行恢复保存，先另存两个损坏原文件为 `.corrupt-<编号>`。恢复使用新修订号，已有有效版本时拒绝恢复覆盖。

HTTP 保留 loopback Host/Origin 约束；只有编辑器页面允许同源嵌入，其余页面保持 frame-ancestors none。Electron 保留 contextIsolation、sandbox 等现有边界；IPC 不接受渲染器提供的任意文件路径或裸配置，校验发送窗口、保存修订及播放器 ACK。场景 IPC 使用生成的旧表达式白名单加四个新场景。

## 4. Watch 参数格式与坐标映射

Watch 使用 `gork-watch-motion` v1，sourceVersion=2，revision 为非零 uint32。每场景固定 eyes[10]、motion[3]、props[6]，保留所有 v2 参数，闲置 props 补零，笔型编码 0/1/2/3 对应 quill/nib/pencil/brush。C++ 在 configure 时拒绝非法版本、倒退修订、NaN、范围或非整数笔型。四场景参数表 304 字节，单姿态 148 字节。

圆心和比例来自实际源码：Watch 466×466，圆心 (233,233)，`grok_renderer.cpp` 的 kBodyInset=17，所以可绘头半径 216；网页当前 Gork 球体半径 120、摄像机距离 620、眼睛尺度 490/260，从现有 avatar-presets、avatar-engine、gork-renderer 提取。桌面透视轮廓半径约 230.512；统一投影比例为 `216 / desktopHeadRadius`。不把桌面像素直接当屏幕坐标。

| 字段 | 校验范围 | Watch 映射及语义 |
| --- | --- | --- |
| eyes.x/y | -20..20 / -35..20 | 保留球面坐标；加到两眼几何中心，再球面投影和统一缩放 |
| eyes.spacing | 28..65 | 左/右中心分别为 -spacing/2、+spacing/2 |
| widthLeft/Right | 8..34 | 左右眼独立胶囊宽度，不合并 |
| heightLeft/Right | 8..65 | 左右眼独立胶囊高度，包含眨眼及加载收眼过渡 |
| headX/Y/Z | -15..15 / -20..20 / -25..25 度 | 俯仰/转头/歪头；按 Rz×Rx×Ry，即 Y→X→Z 顺序旋转后透视投影 |
| motion.speed | 0.25..2.5 | 循环相位时间乘该倍率，不改 enterMs/exitMs 的墙钟时长 |
| enterMs/exitMs | 150..2500 毫秒 | 入场及完成退出使用 smoothstep；返回 idle 使用离开场景的 exitMs；取消上限 400ms |
| loading.x/y | -110..110 | 道具中心桌面设计单位；与网页同样按半径安全内收后统一缩放 |
| loading.scale | 0.5..2 | 白色加载弧半径 32、线宽 9，按参数与入场倍率缩放；旋转相位 t×3.3 |
| writing.x/y | -65..65 / 35..140 | 笔和笔迹整体中心；与网页相同安全内收，不改保存值 |
| writing.scale | 0.65..1.25 | 整体缩放为 0.78×scale，再统一投影缩放；共用 -35 设计单位原点偏移 |
| writing.penScale | 0.6..1.25 | 笔独立缩放，笔尖定位仍跟随当前笔迹末端 |
| writing.strokeWidth | 1.5..5 | 笔迹线宽随整体尺度映射；灰度只用于淡入淡出 |
| writing.penStyle | quill/nib/pencil/brush | 四个独立几何轮廓；Bezier 在 C++ 采样为折线/填充多边形，不降为同一笔型 |
| question.x/y | -145..145 | 问号中心按与网页相同包围圆内收，再统一缩放 |
| question.scale | 0.5..1.5 | 问号几何缩放，保留入场回弹 |
| question.bob | 0..10 | 位移 sin(t×2.7)×bob，t 已乘 speed；保留头部轻歪动 |

idle 包含固定待机眨眼、转头和浮动；loading 入场眼睛收起后显示旋转弧；writing 三行连续笔迹，换行抬笔；question 使用无字体依赖的白色曲线问号。once 周期分别为 loading 2000ms、writing 7199ms、question 3200ms，除以 speed，再加入场时长；完成/取消回 idle。灰度和路径采样是小屏绘制实现差异，不丢配置字段。

保留旧 dirty-rectangle 更新、聊天气泡、调试标记及固件原有帧率门控。新绘制不逐帧堆分配，不新建全屏帧缓存；先测量同一组图元，再清理前后包围区域。眼睛、加载弧、四笔型、笔迹、问号均在真实圆内；像素测试关闭网页 clip 验证，Watch 没有靠圆形遮罩隐藏越界。

## 5. Watch 的交付路径与兼容边界

本期选用“同一保存配置 → 确定性导出 → C++ 头文件 → 编译候选”路线，不实现运行中的 Watch JSON 参数下载。编辑器的“导出 Watch 参数”读取已保存版本，通过 `/api/motion/watch/json` 和 `/header` 下载 Watch JSON 与 `motion_config.h`；未保存草稿不会冒充已保存参数。

转换器也接受 bare v2 JSON 或 motion.local.json 保存记录：

```powershell
& 'Codex-Temp/.venv-companion/Scripts/python.exe' tools/convert_gork_motion.py --source '03-Src/stopwatch-voice-companion/motion.local.json'
& 'Codex-Temp/.venv-platformio/Scripts/python.exe' -m platformio run --project-dir '03-Src/stopwatch-grok-avatar'
```

首次候选的头文件由用户原始快照生成。后续导出的头文件应替换候选源码的 `src/motion_config.h` 后重新编译。JSON 只是可核查参数，不可直接发送给旧设备。本轮未连接、换绑或写入设备。

候选固件串口/原有加密命令入口支持 `once loading`、`loop loading`，同样支持 writing/question；`motion complete`、`motion cancel`、`motion idle`、`legacy idle`，均不超过原 20 字节上限。旧表达式沿原协议播放；legacy idle 为原待机回退，motion idle 恢复配置后的待机。没有放宽 BLE 鉴权或改变音频协议。

当前正式电脑后端对 loading/writing/question 的 Watch/两端目标明确拒绝并提示需要新固件，不对仍是 v0.9.1-dev 的设备发送不支持命令。以后如要控制候选设备，需增加显式能力协商与正式控制入口，并单独验收；现有 ASCII 固件命令可在当次授权后的测试工具中验证。本期参数转换、C++ 适配、编译/仿真已交付，运行时下发不在已完成范围。
