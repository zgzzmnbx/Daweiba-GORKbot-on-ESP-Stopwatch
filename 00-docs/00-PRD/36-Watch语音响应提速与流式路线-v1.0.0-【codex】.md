# Watch 语音响应提速与流式路线

## 2026-10-05 第一项已实施：PC v0.20.22候选

Wi-Fi最多三块PULL在途已实现；现有协议按offset分别回应，四槽队列保留一槽控制余量，无新增协议或固件。客户端等待器按offset分开，重组严格长度，乱序/重复不重复样本，缺块/过期epoch/断线终止而不重播；BLE保持串行。隔离96KB模拟往返等待约0.39→0.15秒，不能外推真机比例。

计时新增编码、音频发送、设备播放和停录到播放回执；后者从PC收到RECORDED至PLAYING回执，不能冒充物理按键到实际可闻首声。传输与播放仍显示为合计，各子项与合计不能相加。录音阶段使用当前“我的疑惑”，回答生成/合成/播放阶段使用“我的书写”；本地库参数保持原样，取消/失败/结束清理。

自动测试见v0.20.22验收记录；正式仍v0.20.18/Wi-Fi，需正常重开和用户同句复测。Watch v0.11.7未改，旧BLE中文回执仍待v0.11.8当次授权。P2云流式/设备环形播放和P3模型SSE、录音中上传均未实施，原性能/长稳延期保留。

文档v1.0.0，2026-10-04。用户本轮要求默认按键对话、加快识别/回答/语音及即时录制提示。本文件区分当前实施和尚待协议开发的流式路线，补充PRD34/任务书35；短按开/再按发以v0.11.6为准。

## 已有链路与本轮实施

当前：短按 → PC建立音频会话 → Mic录音 → 完整PCM拉回电脑 → 本机ASR → DeepSeek完整文字 → 云端完整WAV合成并下载 → Opus编码 → 全段传到Watch → COMMIT → 对应文字 → PLAY。回复端压缩已启用，录音回传未压缩；没有边传边播。DeepSeek Flash关闭思考、默认尽量20字、64tokens预算已有，完整性检查拒绝残句。短答优化保持，避免为20字回答反复切句造成多个云请求。

PC0.20.11/Watch0.11.7候选已做：默认开启意图和关闭记忆；麦克风关闭的HELLO预热；空闲首次短按不取消预热；移除1秒固定再就绪等待；准备/REC立即切换；分段耗时。源码/自动检查通过，候选未烧录，真机速度尚无新对照。

## 现场观察与优化次序

正式PC0.20.10一次录音上传状态：PCM总179840字节，进行中采样约19KB/s。不能据此宣称稳态速度，但录音上传可能比约1秒回答更耗时，必须先量化。取相同1/3/5秒录音各5轮，分开记物理按键→真实REC、停止→上传完、ASR、AI首字/全文、TTS首块/全文、传输首播/完成、实际耳听首声。跨设备单向物理延迟以录像/设备日志同步确认，PCprepare只计PC收到事件后的部分。

| 优先级 | 改造 | 验收与边界 |
| --- | --- | --- |
| P1 | 录音回传拉取流水线，Wi-Fi最多3块在途；能力协商后才使用 | 现PULL逐块等待；扩展分offset等待器/顺序拼装，队列容量4留控制余量，错序/丢包/重复/撤销/断链测试；旧客户端和BLE兼容回退，失败不重复发旧问题 |
| P2 | 独立语音服务新增Realtime TTS分片入口 | 沿用原Key环境变量和文字上传许可；现完整WAV接口保留。Qwen realtime PCM分片转20ms Opus帧，速率/音色/地区协商，不假称把非Realtime模型加stream字段即可 |
| P2 | Watch新增版本化流播放能力，环形缓冲与首块播放 | 先扩展CAPS，STREAM_BEGIN/DATA/END及STOP；约200–400ms首缓冲为待测参数。明确session/epoch/transfer/序号、背压、水位、欠载、最多10秒、解码线程/播放并发、打断清空、未知总长EOS排空；保留旧BEGIN/COMMIT/PLAY全段模式 |
| P3 | DeepSeek SSE文字流接入会话及TTS | 先用完整短句/标点或最终合法结果提交，避免汉字半句频繁合成。streaming只提前首字，不保证总模型计算更快；不播放reasoning_content，最终状态非stop标失败，已播部分不能撤回需明确中断态 |
| 后续 | ASR录音中上传/设备Opus编码或语音模型直接音频回答 | 本地ASR已有很短实测片段，先查瓶颈；新云ASR/一体语音模型涉及供应商/许可/隐私与费用改变，不能自动换掉DeepSeek或绕过本地偏好 |

目标链路：完整录音更快送电脑 → 本地ASR → DeepSeek SSE可用短句 → Qwen Realtime边合成 → PC逐帧Opus → Watch少量预缓冲即播放。不是将已经生成的完整WAV切块后称为云流式，也不是简单提前PLAY让不完整旧音频协议播放。

## 正确性门禁

每轮固定一个已认证健康链路，网络断线只结束本轮，不自动把半句搬到BLE或重新询问模型。所有分片携带本轮身份，取消/新会话/新短按立即停止上下游，丢弃旧分片，麦克风和扬声器占用受控。两链路重连、陌生端、取消的测试必须覆盖已有音频与默认表情。Wi-Fi/BLE共存保持modem sleep限制。新增固件仅当次授权写app0，不清绑定或热点。

真实TTS改造需完整mock分片/音频格式/中断/背压测试，官方云接口单次实测在已有用户许可范围内通过正常应用操作；自动检查不能代替可闻首声、无断音和长稳验收。候选流式尚未实施，不能标完成。

## 官方能力依据（2026-10-04查询）

- [DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)：stream=true支持SSE内容增量；当前源码仍stream=false。
- [Qwen-TTS Realtime WebSocket流程](https://help.aliyun.com/zh/model-studio/interactive-process-of-qwen-tts-realtime-synthesis)：支持text append/commit及audio delta，示例Cherry/PCM/24000Hz；当前云服务qwen3-tts-flash完整URL返回实现未接Realtime。

以上是官方接口能力，不是本机真实模型吞吐或Watch流播放证据。本轮没有工具调用真实模型，不读取/使用聊天中的Key。
