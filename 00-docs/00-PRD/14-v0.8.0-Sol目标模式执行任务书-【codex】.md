## 6. M3：设备声音库与音量

先补协议测试，再改固件；不在 BLE 回调直接开 I2S。

1. 制作六个短音效和来源 manifest；原创合成亦可。转换为总计≤128,000 bytes 的 16k PCM16 单声道 Flash const 数组。转换器检查重复 ID、长度、格式、峰值和时长。
2. 增加音频所有权协调，保证静态音效、Mic、动态 PCM 只有一项占用资源；释放前等待库任务结束，避免引用失效。
3. 实现 catalog/capabilities、play、stop、音量与状态，绑定/加密/定向通知保持。每请求明确 ID 与生命周期回执；客户端断连不自动补播。
4. 产品表情页可遥控播内置声；录音仍限制显式音频页。B 停止优先、BUSY 明确，不新增无限播放队列。
5. Settings 增加设备音量/静音/显式试听、NVS 延迟持久化；控制台镜像回执值并区分电脑音量。
6. 在控制台声音库提供电脑试听/设备播放/停止、固件能力不支持提示。

测试：ID 去重、未知声音、越界音量、20-byte MTU、未绑定拒绝、取消插队、断连释放、Mic/播放互斥、静音映射和 NVS 写入策略。构建统计与旧版对比，不扩分区。

固件产物单独版本化；未获当次烧录授权时停在构建门禁，继续 M4/M5 的桌面与模拟工作。收到授权后重新识别端口/MAC/分区，只写应用区；不重新计算例行文件哈希。

## 7. M4：可视化延迟语音

- 将现有 AudioClient 接入统一 BLE 管理，不同时创建旧控制器与音频控制器。
- 实测并记录同时需要多服务时的 WinRT 发现策略；沿用指定服务+UNCACHED 的已知兼容经验，但必须验证新声音服务和旧表情服务都可用。
- UI 支持 PC 输入→设备延迟播放、设备输入→PC 播放、设备输入→设备延迟回复/跟读。页面明确非实时及预期等待，设备输入仍须用户按 A。
- 对 record 的 Pull 和 play 的 Data 增加真实累计进度、速率和取消；读取到 Recording/Recorded 时立即更新阶段，不静默等待整段。
- 旧固件仅诊断页允许录放时准确提示，不宣称新能力；三种模式都有输入输出明确标签。
- 单包窗口可保留，不同时实施压缩/实时流等大改。音频输入10秒上限、输出10秒和缓冲限制前置检查。

测试：传输慢但进度持续、包丢失/超时/乱序、各阶段取消、途中切模式、旧回执、页面关闭、回连不补播；没有权限不自动改电脑外放。
