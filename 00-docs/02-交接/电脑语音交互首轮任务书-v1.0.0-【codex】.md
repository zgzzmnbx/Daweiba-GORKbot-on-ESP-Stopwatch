先读 README、AGENTS、当前计划，再读 [冻结接口契约](StopWatch-语音服务接口契约-v1.0.0-【codex】.md)。契约由语音任务维护，此任务发现缺口时回传具体请求/响应，不自行平行修改语音源码。

## 文件责任与实现选择

在 StopWatch 的 03-Src/stopwatch-voice-companion/ 新建独立电脑端程序及测试，沿用 Python 小型 HTTP 后端 + 浏览器界面；由后端调用独立语音服务并持有 BLE 连接。复用协议时先把现有 BLE 客户端抽为可导入模块、保留旧控制台入口并跑旧测试；不要依赖另一个仓库绝对路径导入，也不复制语音引擎。
运行环境独立于 PlatformIO；根目录提供双击启动器、配置示例和设备地址/服务地址配置。浏览器麦克风/扬声器仍在电脑；禁止直接跨源调用 8765。启动器验证自有 PID，不停止用户其他 Python 服务。

## 按顺序实施

| 任务 | 交付与验证 |
| --- | --- |
| S1 接口客户端 | health、会话、选路、turn、ASR、TTS、取消、退出；测试 409 会话占用和 401 失效；不默认抢占网页 |
| S2 BLE 适配 | 发现/配对/连接/断开、串行队列、严格回执、有限重连、短气泡；覆盖旧回执、BUSY、丢回执、断开、中文分包；保留旧控制台行为 |
| S3 跟读工作台 | PC 录音→转写→可编辑文字→回读；两项云上传独立说明并应用；本地 ASR + 云端 TTS 为建议选择，初次上传仍要用户勾选 |
| S4 状态联动 | idle/listening/processing/speaking/error 映射到实际存在的表情，读取真实目录后确定名字；播放启动/结束由电脑播放器驱动，不假装逐音素嘴型 |
| S5 停止与恢复 | 停止优先本地静音，旧 generation 的 HTTP/BLE/播放回调无效；20 次中途停止测试，断开设备后电脑功能仍可用 |
| S6 交付 | 自动测试、无硬件模拟、实机 BLE 和真人录音/听验分别报告；更新版本、README/PRD/CHANGELOG，按阶段规则本地 Git 存档 |

## 首轮验收

- 无设备时可录音、听写、回读，提示设备离线；语音服务未启动有可操作提示。
- 已配对设备上，录音/处理/播报/停止的表情和短气泡可观察；BLE 发包成功不等于显示正确。
- 云端 Key 只在语音服务后端；机器人项目不读取或保存阿里云 Key，配置完成不自动开启上传。
- 切换模式、新录音、取消、设备重连都不播放旧结果；会话被接管停止本地播放并提示，不反复抢回。
- 真实设备检查前先列出设备准备步骤（BLE ON，首次 Pair，退出 Settings）；不硬编码历史 MAC/COM5。
- 保留现有 v0.5.0 固件，首轮不烧录。后续设备收音/出声需单独实现协议、构建、恢复准备和当次烧录授权。
- 跟读不是 AI 问答。造价智算和通用 LLM 暂不接入；先把可验证的交互闭环完成。
