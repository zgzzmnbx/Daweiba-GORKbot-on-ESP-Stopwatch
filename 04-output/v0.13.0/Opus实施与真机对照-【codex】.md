# v0.13.0 控制台 / v0.9.0 Watch：Opus 经 BLE 传输

日期：2026-09-24。范围为当前已绑定 StopWatch 的 app0 应用区和 Gork 本机代码；未改分区表、NVS、另一应用区、eFuse 或外部服务凭据。

## 实现

- 电脑端在 HELLO 使用 `0xF00D` transfer ID 请求扩展能力；新固件返回五字节 CAPS，第五字节 bit0 表示支持 Opus。旧固件保持四字节 CAPS，电脑端自动退回 PCM。测试入口可显式选 `pcm16` 或 `opus`，便于同音频对照。
- PC 使用 soundfile/libopus 将完整 PCM16 单声道 WAV 编为 Ogg Opus，再只提取音频包，以两字节长度前缀通过已有加密 BLE 音频服务传输。`BEGIN_OPUS=10` 携带编码总字节、目标采样数、预跳过采样数。Watch 收齐并 COMMIT 后用 libopus 解码，去掉预跳过及尾部填充，再经现有小人页扬声器播放。
- 保留 10 秒、480,000 字节设备缓冲、三包发送窗口、逐包设备回执、取消与断线边界。控制台展示编码格式、实际传输字节、原始 PCM 字节和 ACK 速率。当前仍是整句合成、整句传输、再播放；语音服务的 TTS 接口仍返回完整 WAV。

## 同一 WAV 的真机对照

测试音频：项目本机 SenseVoice 自带 `Codex-Temp/voice-runtime/models/sensevoice/test_wavs/zh.wav`；PCM16 单声道 16 kHz、5.592 秒。两次均在普通小人页，通过同一 Watch、244 字节 BLE 包、最多三包在途传输，设备均回 `PLAYING` 与 `PLAYED`，无协议错误。

| 编码 | BLE 数据量 | 发送阶段 | 从编码开始至设备 `PLAYED` |
| --- | ---: | ---: | ---: |
| PCM16 | 178,944 字节 | 32.22 秒 | 38.22 秒 |
| Opus | 18,748 字节 | 3.66 秒 | 10.02 秒 |

这段样本的传输字节减少约 89.5%，发送阶段约快 8.8 倍，从编码到设备播放结束约快 3.8 倍。两次发送速率约为 5.1–5.6 KB/s，因此主要收益来自压缩，并非 BLE 链路本身提速。上述总时间包含 5.592 秒音频的播放等待，但不包含 BLE 扫描/连接或云端 TTS 合成。数值只代表该样本与本次设备状态。`PLAYED` 不证明实际可闻或音质；用户听验另记。

正式 8766 后端 v0.13.0 已启动并自动连回 Watch。对话页选“Watch 朗读（实验）”，输入“你好，测试完成。”，实际云端 TTS → 设备音频任务依次进入 `sending · Opus`、`playing · Opus`、`played · Opus`，页面正确显示“Watch 报告播放完成”。应用户要求再次播放同句，第二次也收到完整的 Opus 发送、播放及结束回执。**用户当场确认 Watch 在普通小人页完整念完并实际听到声音，并主观认为 Opus 音色可以接受。** 本轮未量化 Opus 与 PCM 的音质差异，也未检查动画帧率和气泡。
