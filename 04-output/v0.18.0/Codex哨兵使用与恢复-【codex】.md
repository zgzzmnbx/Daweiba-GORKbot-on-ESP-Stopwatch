# Codex 哨兵使用与恢复（v0.18.0-dev）

本功能用于个人本机只读观察，不向 Codex 发送任务控制命令。正式控制台必须先通过 `/api/health` 确认运行版本已加载 v0.18.0-dev；仅源码更新不会改变已运行的 8766 或 Electron。Codex 哨兵与造价哨兵开关独立，Codex 每次后端启动默认关闭。

1. 打开控制台“Codex”页，取得工作台控制权，开启监测。另一标签页占用时使用页面的“接管工作台”，由用户确认后再操作。普通新标签只读查看状态无需控制权。
2. “自动关注”适合看最近观察到的任务；“指定任务”需要选择真实观察到的会话 ID。选择桌面、Watch 或两端，再决定是否启用短提示音及其唯一目标。声音默认关闭，不调用云 TTS。
3. 额度来自当前本机 Codex CLI 登录账号的官方 app-server。页面按返回的桶/窗口显示剩余值和重置时间；未知、接口不支持和样本过期会单独标明。手动刷新与周期读取合并，关闭后不再启动额度进程。桌面小人细环对应同一桶的最多两个真实窗口，不代表任务进度。
4. 默认 JSONL 来源只可靠提供“工作中”和“本轮已结束”；“本轮结束”不代表目标已完成。首次启用与断线恢复只建立历史基线。启用前已运行且尾部缺开始事件的长轮次，可能等到下一轮才显示可信运行状态。旧日期目录每 60 秒低频发现，最多跟踪最近修改的 40 个文件；超过预算的会话可能延迟或缺失，页面不得宣传全量实时。
5. 若需要审批信号，先在**本机指定的** hooks.json 上运行 `python tools/codex_sentinel_hooks_config.py <hooks.json>` 查看 dry-run 输出。输出命令固定使用运行该工具时的 `sys.executable` 绝对路径，审查时须核对目标 Python 环境仍存在且能导入本项目；跨环境复制配置可能失效。确认目标、其他既有条目与信任影响后，才由用户决定是否执行 `--apply` 和 Codex 信任步骤。本版未安装全局 hook；桥没有租约时空输出退出，也不会写入事件。不要把测试中的桥事件当作已信任的真实审批。输入超过 1 MiB 会安全忽略该事件。

立即停止：Codex 页关闭开关可停止本监测；“停止全部”会停止当前后端的两类哨兵、待发提醒、自有音频与额度子进程，即使旧工作台标签页仍占用也可调用。停止不会中断、恢复或更改 Codex 任务。误报排查时记录 `/api/health` 运行版本、来源能力、`source_at`/`detected_at`/`response_started_at` 和任务状态，不复制 JSONL 原始正文或凭据。配置偏好存于项目忽略的本机文件；下次启动仍需手动开启。

回退：先关闭开关或“停止全部”，退出正式 Gork 后由维护者从本地 Git 快照恢复相应源码与配置，再重新构建 UI/启动。禁止用 `git reset --hard` 覆盖用户当前 dirty 工作；先核对快照 ref 与文件差异，按路径选择恢复。固件和 Android 不属于此次回退范围。
